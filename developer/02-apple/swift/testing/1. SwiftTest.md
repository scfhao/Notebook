
## 定义测试函数

1. 导入测试库

```swift
import Testing
```

> 只建议在测试 target 中导入 Testing 库。因为发布构建不会自动去除测试函数。

2. 定义测试函数

前面添加`@Test`属性的无参函数。

```swift
@Test func testExample() {
    // 测试代码
}
```

此测试函数可位于文件作用域内或类型内部。包含测试函数的类型自动构成测试套件，可选择性地添加`@Suite`属性进行标注。

3. 自定义测试名称

```swift
@Test("Food truck exists") func foodTruckExists() { ... }
```

4. 编写并发测试或抛出异常的测试

如果某个测试仅能在 MainActor 的执行上下文中安全运行（即从进程的主线程运行），则可为其添加`@MainActor`注解：

```swift
@Test @MainActor func foodTruckExists() async throws { ... }
```

5. 限制测试的可用性

如果测试函数仅能在较新版本的操作系统或 Swift 语言上运行，请在声明时使用`@available`属性。通过该属性的 message 参数，可指定当测试因可用性受限而无法运行时要记录的日志信息：

```swift
@available(macOS 11.0, *)
@available(swift, introduced: 8.0, message: "Requires Swift 8.0 features to run")
@Test func foodTruckExists() { ... }
```

## 使用套类型组织测试

包含测试函数的类型就是测试套件，可选择性地添加`@Suite`属性进行标注，可以通过这个属性对套件进行更多自定义的设定，默认情况下一个套件中的测试函数是并行运行的。

如果测试套件中的测试方法是实例方法，测试时会自动创建该类型的对象，然后调用该方法。如果套件有多个测试方法，每个方法都将在不同的对象实例上运行。这类情况套件需要可以通过无参构造器实例化。

自定义套件名称：

```swift
@Suite("Food truck tests") struct FoodTruckTests {
  @Test func foodTruckExists() { ... }
}
```

套件类型不能使用`@available`属性进行标注，否则编译器会报错。
