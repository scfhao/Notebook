# 使用 Combine 接收和处理事件

自定义并接收来自异步源的事件。

## 概述

Combine 框架为应用程序如何处理事件提供了声明式方法。无需实现多个委托回调或完成处理器闭包，您只需为特定事件源创建单一处理链。链中的每个环节都是 Combine 运算符，对从前一步接收到的元素执行特定操作。

假设有一个应用程序需要根据文本字框的内容过滤列表或集合视图。在 AppKit 中，文本框中的每次按键操作都会产生一个通知，你可以使用Combine 订阅该通知。收到通知后，你可以使用运算符来改变事件传递的内容和时机，并使用最终结果更新应用程序的用户界面。

### 连接发布者到订阅者

要通过 Combine 接收文本框的通知，请访问默认的 NotificationCenter 实例并调用其`publisher(for:object:)`方法。该调用需要通知名称和源对象（即您希望接收通知的对象），并返回一个会生成通知元素的发布者。

```swift
let pub = NotificationCenter.default
    .publisher(for: NSControl.textDidChangeNotification, object: filterField)
```

订阅者用于从发布者接收元素。订阅者定义了一个关联的 Input 类型，用来声明它接收的类型。发布者订阅了一个 Output 类型，声明它生成的类型。订阅者和发布者都定义了一个 Failure 类型，用来指明它们产生或收到的错误类型。把订阅者连接到生产者时，Output 和 Input 必须匹配，且两个 Failure 类型也必须匹配。

Combine 提供了两个内置的订阅者，它们会自动匹配所连接的发布者的 Output 和 Failure 类型：

- `sink(receiveCompletion:receiveValue:)` 接收两个闭包，第一个闭包在它接收到`Subscribers.Completion`时调用(这是一个代表发布者正常结束或因错误失败的枚举值)，第二个闭包在每次接收到新元素时调用。
- `assign(to:on:)` 立即将接收到的每个元素分配给指定对象的属性，使用键路径来指示该属性。

例如，你可以使用 sink 订阅者来记录发布者完成操作的时间，以及每次接收元素的时间：

```swift
let sub = NotificationCenter.default
    .publisher(for: NSControl.textDidChangeNotification, object: filterField)
    .sink(receiveCompletion: { print ($0) },
          receiveValue: { print ($0) })
```

无论是`sink(receiveCompletion:receiveValue:)`还是`assign(to:on:)`订阅者，都会向发布者请求无限数量的元素。若要控制接收元素的速度，请通过实现 Subscriber 协议来创建自己的订阅者。

### 使用运算符改变输出类型

上一节中的 sink 订阅者在接收值闭包中完成所有工作。若需对接收到的元素执行大量自定义操作，或在调用间隔中维护状态，这可能造成负担。Combine 的优势在于通过组合运算符来定制事件传递。

例如，当你只需要文本框的字符串值时，回调中接收 doc://com.apple.documentation/documentation/Foundation/NotificationCenter/Publisher/Output 类型并不方便。由于发布者的输出本质上是随时间推移的元素序列，Combine 提供了序列修改运算符，如`map(_:)`、`flatMap(maxPublishers:_:)` 和`reduce(_:_:)`。这些运算符的行为与 Swift 标准库中的对应运算符类似。

要更改发布器的输出类型，需添加一个闭包返回不同类型的`map(_:)`操作符。在此情况下，可将通知对象转换为 NSTextField，随后获取该字段的stringValue属性。

```swift
let sub = NotificationCenter.default
    .publisher(for: NSControl.textDidChangeNotification, object: filterField)
    .map { ($0.object as! NSTextField).stringValue }
    .sink(receiveCompletion: { print ($0) },
          receiveValue: { print ($0) })
```

在发布者链生成所需字符串后，将`sink(receiveCompletion:receiveValue:)`替换为`assign(to:on:)`。以下示例将发布者链接收的字符串赋值给自定义视图模型对象的`filterString`属性：

```swift
let sub = NotificationCenter.default
    .publisher(for: NSControl.textDidChangeNotification, object: filterField)
    .map { ($0.object as! NSTextField).stringValue }
    .assign(to: \.filterString, on: viewModel)
```

### 使用运算符自定义发布者

您可以通过操作符扩展发布者实例，该操作符可执行原本需要手动编码的操作。以下是三种利用操作符优化此事件处理链的方法：

* 与其将文本字段中输入的任何字符串都更新到视图模型中，不如使用`filter(_:)`运算符来忽略长度不足的输入，或拒绝非字母数字字符。
* 如果过滤操作耗时较长（例如查询大型数据库），您可能需要等待用户停止输入。为此，`debounce(for:scheduler:options:)` 操作符允许您设置发布者在发出事件前必须经过的最小时间间隔。`RunLoop` 类提供了便捷方式，可使用秒或毫秒为单位指定延迟时间。
* 如果结果更新了用户界面，您可以通过调用`receive(on:options:)`方法将回调传递到主线程。通过将`RunLoop`类提供的`Scheduler`实例指定为第一个参数，您告知 Combine 在主运行循环上调用您的订阅者。

由此产生的发布者声明如下：

```swift
let sub = NotificationCenter.default
    .publisher(for: NSControl.textDidChangeNotification, object: filterField)
    .map( { ($0.object as! NSTextField).stringValue } )
    .filter( { $0.unicodeScalars.allSatisfy({CharacterSet.alphanumerics.contains($0)}) } )
    .debounce(for: .milliseconds(500), scheduler: RunLoop.main)
    .receive(on: RunLoop.main)
    .assign(to:\MyViewModel.filterString, on: myViewModel)
```

### 需要时取消发布

发布者会持续发出元素，直至正常完成或失败。若不再需要订阅发布者，可取消订阅。由`sink(receiveCompletion:receiveValue:)`和`assign(to:on:)`创建的订阅者类型均实现了`Cancellable`协议，该协议提供了`cancel()`方法：

```swift
sub?.cancel()
```

若创建自定义 Subscriber，发布者会在首次订阅时发送 Subscription 对象。请保存此订阅对象，并在需要取消发布时调用其`cancel()`方法。创建自定义订阅者时，应实现`Cancellable`协议，并在`cancel()`方法中将调用转发至已保存的订阅对象。
