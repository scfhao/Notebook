# 并发

异步函数或方法与普通函数或方法直接的区别就是异步函数或方法在执行途中可以被挂起，函数/方法内部等待某些事物的时候可以暂停。在异步函数/方法体中，我们需要标记每个可以挂起的地方。

在函数参数后面使用`async`关键字来标记一个函数或方法是异步的。

```swift
func listPhotos(inGallery name: String) async -> [String] {
    let result = // ... 一些异步网络代码
    return result
}
```

如果一个函数既是异步的又是可抛出的，把`async`关键字放到`throws`关键字之前。

由于`await`标记的代码需要可以被挂起，所有在我们代码中特定的地方才能调用异步函数。

* 异步函数、方法或属性中
* 在结构体、类或枚举的静态 main() 方法中编写的代码，该方法需标记为 @main。
* 在非结构化子任务中编写代码

```swift
func listPhotos(inGallery name: String) async throws -> [String] {
    try await Task.sleep(for: .seconds(2))
    return ["IMG001", "IMG99", "IMG0404"]
}
```

要让异步函数与它周围的其他代码同时运行，添加`async`关键字，并在需要用到异步函数结果的地方使用`await`关键字。

```swift
async let firstPhoto = downloadPhoto(named: photoNames[0])
async let secondPhoto = downloadPhoto(named: photoNames[1])
async let thirdPhoto = downloadPhoto(named: photoNames[2])

let photos = await [firstPhoto, secondPhoto, thirdPhoto]
show(photos)
```

## Task 和 TaskGroups

Task 是程序中可以异步执行的工作单元。所有的异步代码作为一些 Task 的组成部分。前面提到的`async-let`语法隐式创建了一个子 Task。你也可以创建任务组并添加自任务到任务组，这样在优先级和取消方面就有了更多的控制，还能创建动态数量的任务。

结构化并发：任务组中的任务的父任务相同，每个任务可以有自己的子任务。任务和任务组之间有明确的父子关系，优势有：

* 在父任务中不会忘记等待子任务都结束
* 为子任务设置更高的优先级后，父任务优先级自动提升
* 父任务被取消后，子任务自动取消
* 任务局部值能高效且自动地传播到子任务中

```swift
await withTaskGroup(of: Data.self) { group in
    let photoNames = await listPhotos(inGallery: "Summer Vacation")
    for name in photoNames {
        group.addTask {
            return await downloadPhoto(named: name)
        }
    }

    for await photo in group {
        show(photo)
    }
}
```

如果下载图片的代码会抛出错误，我们需要替换为使用`withThrowingTaskGroup(of:returning:body:)`。

一个有返回值的示例：

```swift
let photos = await withTaskGroup(of: Data.self) { group in
    let photoNames = await listPhotos(inGallery: "Summer Vacation")
    for name in photoNames {
        group.addTask {
            return await downloadPhoto(named: name)
        }
    }

    var results: [Data] = []
    for await photo in group {
        results.append(photo)
    }

    return results
}
```

使用取消机制的示例：

```swift
let photos = await withTaskGroup { group in
    let photoNames = await listPhotos(inGallery: "Summer Vacation")
    for name in photoNames {
        let added = group.addTaskUnlessCancelled {
            Task.isCancelled ? nil : await downloadPhoto(named: name)
        }
        guard added else { break }
    }

    var results: [Data] = []
    for await photo in group {
        if let photo { results.append(photo) }
    }
    return results
}
```

## 非结构化并发

非结构化任务没有父任务，根据程序需要灵活管理非结构化任务。

## 主Actor

有多种方式可以在主Actor上运行代码，可以在一个函数上标记`@MainActor`来确保它在主Actor上运行。

```swift
@MainActor
func show(_: Data) {
    // 更新UI显示图片
}
```

`@MainActor`属性要求`show(_:)`方法在主Actor上运行。其他在主 Actor 上运行的代码可以像同步函数一样调用`show(_:)`方法，而不在主Actor上运行的代码需要使用`await`关键字像异步函数方式调用`show(_:)`函数。

要确保一个闭包运行在主Actor上，需要在闭包的`in`前添加`@MainActor`属性。

```swift
let photo = await downloadPhoto(named: "Trees at Sunrise")
Task { @MainActor in
    show(photo)
}
```

我们也可以在结构体、类、枚举上添加`@MainActor`属性，这样可以确保所有调用它的方法或者访问它的属性的代码在主Actor上运行。

由于在SwiftUI中`View`协议已经添加了`@MainActor`属性，所以在我们自己的视图类型上再添加此注解。对于更细粒度的控制，可以只在需要在主Actor上运行的方法或属性上添加`@MainActor`属性。

## Actor

实现自己的 Actor。Actor 也是引用类型。actors 在同一时间只允许一个任务访问它的可变状态。

```swift
actor TemperatureLogger {
    let label: String
    var measurements: [Int]
    private(set) var max: Int // 该 Actor 中的代码才能修改此属性值

    init(label: String, measurement: Int) {
        self.label = label
        self.measurements = [measurement]
        self.max = measurement
    }
}
```

我们在访问 actor 上的属性和方法时，需要加上`await`关键字(在Actor内部访问自己的属性时则不需要`await`关键字)。

```swift
let logger = TemperatureLogger(label: "Outdoors", measurement: 25)
print(await logger.max)
// Prints "25".
```

## Sendable

可以在并发域间共享的类型被称为`Sendable`类型。一般有三种方法可以把一个类型变为`Sendable`类型：

* 该类型是值类型，且它的可变状态是 sendable 的。
* 该类型没有可变状态，且其不可变状态是 sendable 的。如只有只读属性的结构或类。
* 类型本身有确保其可变状态安全的机制，如有`@MainActor`标记或者把访问可变状态的代码放到特定的线程或队列中。

显示标记一个类不是`Sendable {}`:

```swift
struct FileDescriptor {
    let rawValue: Int
}

@available(*, unavailable)
extension FileDescriptor: Sendable {}
```
