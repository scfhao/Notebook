# 用 Timer 发布者替换 Foundation Timers

使用定时器定期发布元素。

## 概述

如果您的应用程序使用 Foundation 的 Timer 类在指定间隔内反复接收回调或调用闭包，您可以将这些实例转换为 Combine 以简化代码。

## 使用定时器执行周期性任务

请考虑以下代码片段，它使用`scheduledTimer(withTimeInterval:repeats:block:)`在特定调度队列上每秒更新一次数据模型的`lastUpdated`属性：

```swift
var timer: Timer?
override func viewDidLoad() {
    super.viewDidLoad()
    timer = Timer.scheduledTimer(withTimeInterval: 1, repeats: true) { _ in
        self.myDispatchQueue.async() {
            self.myDataModel.lastUpdated = Date()
        }
    }
}
```

## 转换为 Timer 发布者

要将此代码迁移至 Combine，请将`scheduledTimer(withTimeInterval:repeats:block:)`返回的`Timer`替换为`Timer.TimerPublisher`。通过`Timer`的`publish(every:tolerance:on:in:options:)`方法创建该发布器。每次底层定时器触发时，发布器都会发出一个新`Date`对象，该对象表示定时器触发的具体时刻。随后可对`Date`对象应用`Combine`运算符，最终将发布器连接至订阅器（如`sink(receiveValue:)`或`assign(to:on:)`）。

> 由于`Timer.TimerPublisher`遵循`ConnectablePublisher`协议，它不会在您显式连接之前生成元素。可通过调用`connect()`方法实现连接，或使用`autoconnect()`操作符在订阅者附加时自动完成连接。

下一个示例展示了如何使用`Timer.TimerPublisher`替代前一个示例。它利用 Combine 的操作符来执行前一个示例闭包中的任务：

```swift
var cancellable: Cancellable?
override func viewDidLoad() {
    super.viewDidLoad()
    cancellable = Timer.publish(every: 1, on: .main, in: .default)
        .autoconnect()
        .receive(on: myDispatchQueue)
        .assign(to: \.lastUpdated, on: myDataModel)
}
```

在此示例中，Combine 操作符替换了先前示例闭包内部的所有行为：

* `receive(on:options:)`操作符确保后续操作符在指定调度队列上运行。这取代了之前的`async()`调用。
* `assign(to:on:)`操作符通过使用键路径设置`lastUpdated`属性来更新数据模型。

使用Combine简化代码的另一个优势在于`Timer.TimerPublisher`会生成新的`Date`实例作为输出类型。第一个示例中的闭包将`Timer`本身作为参数接收，因此必须手动创建新的`Date`实例。
