# 在应用程序的异步代码中使用 Combine 实现

应用常见模式迁移基于闭包的事件处理代码。

## 概览

我们的应用程序可能采用常见模式处理异步事件，例如：

* 完成处理器：调用方提供一个闭包，用于在可能耗时的任务完成后执行一次。
* 闭包属性：调用方提供闭包，在指定异步事件每次发生时触发。

Combine 为这些模式提供了强大的替代方案，既能消除冗余实现，又能充分利用其丰富的运算符。当您在应用其他模块采用 Combine 时，将异步调用点转换为 Combine 模式可显著提升代码一致性与可读性。

> 若使用 Swift 5.5 及更高版本的 async-await 特性，则无需采用基于闭包的异步模式。取而代之的是，您的代码可 await 异步调用完成，随后执行原本应在闭包中执行的代码。这既消除了传统完成处理程序的需求，也无需使用 Combine 特性。更多信息请参阅《Swift 编程语言》中的并发章节。

## 用 Futures 替换完成处理器闭包

完成处理器是由函数接受的闭包，该闭包在函数完成工作后执行。通常实现方式是在函数完成工作时直接调用完成处理器，必要时将闭包存储在函数外部。例如，以下函数接受一个闭包，并在延迟两秒后执行它：

```swift
func performAsyncAction(completionHandler: @escaping () -> Void) {
    DispatchQueue.main.asyncAfter(deadline:.now() + 2) {
        completionHandler()
    }
}
```

你可以用 Combine Future 替换这个模式，它是一个发布器，执行某些工作后会异步发出成功或失败的信号。若成功，该未来对象将执行 `Future.Promise`——一个闭包，用于接收未来对象生成的元素。你可以按以下方式替换之前的函数：

```swift
func performAsyncActionAsFuture() -> Future <Void, Never> {
    return Future() { promise in
        DispatchQueue.main.asyncAfter(deadline:.now() + 2) {
            promise(Result.success(()))
        }
    }
}
```

未来对象在任务完成时不会显式调用闭包，而是调用传递给它的承诺对象，并传入一个表示成功或失败的结果。调用方将异步从未来对象接收该结果。由于`Future`是 Combine 发布者，调用方可将其附加到可选操作符链中，最终连接到订阅者，例如`sink(receiveValue:)`：

```swift
cancelable = performAsyncActionAsFuture()
    .sink(receiveValue: { _ in
        print("Action completed")
    })
```

## 使用输出类型表示未来的参数

有时，一个长期运行的任务会生成一个值，并将其作为参数传递给完成处理器。要在 Combine 中实现此功能，请将该参数声明为未来对象发布者的输出类型。以下示例生成一个随机整数，并通过将 Int 声明为未来对象的输出类型将其传递给承诺：

```swift
func performAsyncActionAsFutureWithParameter() -> Future <Int, Never> {
    return Future() { promise in
        DispatchQueue.main.asyncAfter(deadline:.now() + 2) {
            let rn = Int.random(in: 1...10)
            promise(Result.success(rn))
        }
    }
}
```

通过声明未来将产生 Int 元素，该未来即可使用 `Result`类型向承诺传递 Int 值。当承诺执行时，未来会发布该值，调用方可通过订阅器（如 `sink(receiveValue:)`）接收该值：

```swift
cancelable = performAsyncActionAsFutureWithParameter()
    .sink() { rn in print("Got random number \(rn).") }
```

## 用 Subject 替换反复调用的闭包

您的应用程序可能也存在一种常见模式：将闭包作为属性，在特定事件发生时调用。这类属性的名称通常以 on 开头，其调用点如下所示：

```swift
vc.onDoSomething = { print("Did something.") }
```

借助 Combine，您可以通过`Subject`替换此模式。Subject 允许您通过调用`send()`方法，在任何时候以命令式方式发布新元素。采用此模式时，请使用私有的`PassthroughSubject`或`CurrentValueSubject`，然后将其作为`AnyPublisher`公开暴露：

```swift
private lazy var myDoSomethingSubject = PassthroughSubject<Void, Never>()
lazy var doSomethingSubject = myDoSomethingSubject.eraseToAnyPublisher()
```

通过这种安排，调用方无需设置闭包属性，而是在订阅器（如`sink(receiveValue:)`）中执行其工作：

```swift    
cancelable = vc.doSomethingSubject
    .sink() { print("Did something with Combine.") }
```

使用 Combine 的一个优势在于，subject 可以调用`send(completion:)`方法告知订阅者不再有后续事件，或者发生了错误。

> 若在 Swift 5.5 或更高版本中使用 async-await 并发模式，可采用 AsyncStream 替代 Combine Subject 来异步生成新元素。此方案下，调用点将执行 for-await-in 循环遍历流，而非订阅主题。原本应在订阅者的 receiveValue 闭包中执行的代码，现成为 for-await-in 循环的内容。
