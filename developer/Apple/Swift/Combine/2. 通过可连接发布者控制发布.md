# 通过可连接发布者控制发布

协调发布者向订阅者发送元素的时机。

## 概述

有时，你需要在发布者开始生成元素前进行配置，例如当发布者有会影响其行为的属性时。但像`sink(receiveValue:)`这类常用订阅者会立即要求无限制元素，这可能阻碍你按预期配置发布者。当发布者拥有两个或更多订阅者时，过早输出值同样会引发问题。这种多订阅者场景会形成竞争条件：发布者可能在第二个订阅者尚未创建时，就向第一个订阅者发送元素。

请考虑下图（图略）所示的情景。你创建了一个`URLSession.DataTaskPublisher`，并将其与一个 sink 订阅者（订阅者 1）关联，这将触发数据任务开始获取 URL 的数据。在稍后的某个时刻，你又关联了第二个订阅者（订阅者 2）。如果数据任务在第二个订阅者关联之前就完成了下载，那么第二个订阅者将错过数据，只能看到任务完成的状态。

## 通过可连接的发布者实现发布功能

为防止发布者在您准备就绪前发送元素，Combine 提供了`ConnectablePublisher`协议。可连接发布者在您调用其`connect()`方法前不会生成任何元素。即使它已准备好生成元素且存在未满足的需求，可连接发布者也不会向订阅者交付任何元素，除非您显式调用`connect()`方法。

要在自定义的 Combine 代码中使用 ConnectablePublisher，请使用`makeConnectable()`操作符将现有发布器用`Publishers.MakeConnectable`实例进行封装。下面的代码展示了`makeConnectable()`如何修复上述数据任务发布者的竞争条件。通常，附加一个 sink（此处通过其返回的`AnyCancellable`对象`cancellable1`标识）会导致数据任务立即启动。在此场景中，第二个 sink（标识为`cancellable2`）延迟一秒才附加，导致数据任务发布者可能在附加前完成。而显式使用C`onnectablePublisher`时，数据任务仅在应用调用`connect()`后启动——该调用会在两秒延迟后执行。

```swift
let url = URL(string: "https://example.com/")!
let connectable = URLSession.shared
    .dataTaskPublisher(for: url)
    .map() { $0.data }
    .catch() { _ in Just(Data() )}
    .share()
    .makeConnectable()

cancellable1 = connectable
    .sink(receiveCompletion: { print("Received completion 1: \($0).") },
          receiveValue: { print("Received data 1: \($0.count) bytes.") })

DispatchQueue.main.asyncAfter(deadline: .now() + 1) {
    self.cancellable2 = connectable
        .sink(receiveCompletion: { print("Received completion 2: \($0).") },
              receiveValue: { print("Received data 2: \($0.count) bytes.") })
}

DispatchQueue.main.asyncAfter(deadline: .now() + 2) {
    self.connection = connectable.connect()
}
```

> `connect()`返回一个`Cancellable`实例，您需要保留该实例。您可以通过显式调用`cancel()`或允许其反初始化（deinitialize）来取消发布操作。

## 无需显式连接时使用自动连接运算符

某些 Combine 发布者已实现`ConnectablePublisher`接口，例如`Publishers.Multicast`和`Timer.TimerPublisher`。使用这些发布者可能引发相反的问题：若无需配置发布者或附加多个订阅者，显式调用`connect()`会带来额外负担。

针对此类场景，`ConnectablePublisher`提供了`autoconnect()`操作符。当订阅者通过`subscribe(_:)`方法附加到发布者时，该操作符会立即调用`connect()`。

下例使用`autoconnect()`实现：订阅者可立即接收来自每秒触发一次的`Timer.TimerPublisher`的元素。若未使用`autoconnect()`，则需在某个时刻显式调用`connect()`启动计时器发布者。

```swift
let cancellable = Timer.publish(every: 1, on: .main, in: .default)
    .autoconnect()
    .sink() { date in
        print ("Date now: \(date)")
     }
```
