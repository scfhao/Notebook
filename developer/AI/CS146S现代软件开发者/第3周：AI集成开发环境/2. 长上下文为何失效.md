长上下文削弱了检索增强生成（RAG）的热度，推动了模型连接平台（MCP）的热潮。

但实际上，更长的上下文并不会生成更好的回复。让上下文过载会导致你的智能体和应用程序以意想不到的方式出现故障。上下文可能会被污染、产生干扰、造成混乱或出现矛盾。这对智能体来说问题尤为突出，因为它们依赖上下文来收集信息、综合结论并协调行动。

## Context Poisoning 上下文投毒

上下文污染指的是幻觉或其他错误混入上下文中，并在其中被反复引用的现象。

如果其上下文的“目标”部分被篡改，智能体就会制定出毫无逻辑的策略，并为了达成一个无法实现的目标而重复某些行为。

## Context Distraction 上下文干扰

上下文干扰指的是当上下文过长时，模型会过度关注上下文内容，而忽略了其在训练过程中学到的知识。

如果模型在上下文窗口填满之前就开始出现异常行为，那么超大上下文窗口又有什么意义呢？简而言之：就是为了摘要和事实检索。

## Context Confusion 语境混淆

上下文混淆是指模型在生成回复时，使用了上下文中多余的内容，从而导致生成低质量的回复。

一个典型的上下文混淆案例出现在近期一篇论文中，该论文评估了小型模型在GeoEngine 基准测试上的表现，这是一项包含46种不同工具的测试。当研究团队给一个经过量化（压缩）的 Llama 3.1 8B 模型输入包含全部46种工具的查询时，模型失败了，尽管上下文完全在16k上下文窗口的范围内。但当他们只给模型提供19种工具时，模型就成功了。

问题在于：如果你在上下文中放入某样内容模型就必须对其予以关注。这些内容可能是无关信息或多余的工具定义，但模型仍然会将其纳入考量。大型模型，尤其是推理模型，在忽略或剔除多余上下文方面的能力正在提升，但我们仍不断看到无价值的信息会让智能体陷入困境。更长的上下文能让我们塞入更多信息，但这种能力也伴随着弊端。

## Context Clash 语境冲突

语境冲突指的是你在自己的语境中积累的新信息和新工具，与该语境中的其他信息相矛盾的情况。

智能体从文档、工具调用以及负责处理子问题的其他模型中整合上下文。所有这些来自不同来源的上下文都有可能彼此矛盾。此外，当你连接到并非自己开发的 MCP 工具时，它们的描述和说明与你的提示其余部分冲突的可能性会更大。
