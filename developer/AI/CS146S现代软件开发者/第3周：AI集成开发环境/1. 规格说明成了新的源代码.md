来自 OpenAI 的肖恩·格罗夫（Sean Grove）提出了一个颇具争议的论点。在他近期的演讲《新代码》（The New Code）中，他认为一份写得好的提示词（即规范说明）就是新的源代码。

从这个角度看，我们的人工智能开发方式本末倒置。我们精心设计提示词来向模型传达意图，由人工智能生成代码，最后我们只保留代码，却把提示词弃之不用。

我们来看看这个流程中的步骤:

2. 在上方的工单中明确我想要新文案的内容（00:25）
3. 打开 Copilot 并提示 Claude 打开 Linear 工单（01:18）
4. 提示 Claude 审核工单并结合代码库进行分析（01:52）
5. 提示 Claude 创建分支并实施这些更改 (02:30)
6. 测试更改以确保它们按预期工作。（02:52）
7. 在 GitHub 上发起拉取请求（PR），将这些更改合并到代码库中（03:55）
8. 等待工程师审核并批准拉取请求

创造了“赛博空间”这一术语的科幻作家威廉·吉布森曾说：未来已经到来——只是它的分布还不够均匀。

每当我思考人工智能的能与不能时，就会想起这一点。如今，人工智能的进步呈现出极不均衡的态势。有些领域——比如生成代码、文本、图像——已经实现了质的飞跃，它们以人工智能的速度运行。而另一些领域——例如与客户沟通、挖掘客户需求、说服客户购买——仍以人类的速度推进。

这种不均衡的分布正在重塑产品团队。焦点正从执行类工作转向理解类工作。一直以来让最优秀的产品经理脱颖而出的核心技能——理解用户需求、清晰定义问题、设计精妙的解决方案——其价值正呈指数级增长。

最优秀的产品经理会将这些洞察转化为产品需求规格说明——这种规格说明能让团队目标一致，指导开发落地，同时在日益自动化的开发环境中，成为留存下来的核心文档。
