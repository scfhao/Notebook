1. 编辑配置文件内容

ora2pg.conf

```conf
ORACLE_HOME    /u02/app/oracle/product/11.2.4/db1
ORACLE_DSN    dbi:Oracle:host=192.168.56.2;sid=orcl
ORACLE_USER    zhaoxu
ORACLE_PWD    zhaoxu
SCHEMA          zhaoxu
USER_GRANTS     1
DEBUG        0
ORA_INITIAL_COMMAND
EXPORT_SCHEMA    0
CREATE_SCHEMA    1
COMPILE_SCHEMA    0
TYPE        TABLE INSERT
OUTPUT        output.sql
```

默认的配置文件中需要修改的地方：

* ORACLE_HOME 这个会自动配置好
* ORACLE_DSN 自己数据库的信息
* ORACLE_USER 数据库用户名
* ORACLE_PWD 数据库密码
* SCHEMA 数据库模式
* USER_GRANTS 如果使用的数据库用户有DBA权限用0，没有DBA权限用1
* TYPE 导出类型

其中 TYPE 字段的配置需要着重介绍：

- TABLE: 导出所有的表（包括索引、主键、唯一键）
- VIEW: 导出视图
- GRANT: 导出角色到Pg群组，用户和权限
- SEQUENCE: 导出序列和最后位置
- TABLESPACE: 导出表和索引的存储空间
- TRIGGER: 导出触发器
- FUNCTION: 导出函数
- PROCEDURE: 导出存储过程
- PACKAGE: 导出包和包主体
- INSERT: 按INSERT语句格式导出数据
- COPY: 按COPY语句格式导出数据
- PARTITION: Extract range and list Oracle partitions with subpartitions.
- TYPE: 导出用户定义的Oracle类型
- FDW: Export Oracle tables as foreign table for oracle_fdw.
- MVIEW: Export materialized view.
- QUERY: Try to automatically convert Oracle SQL queries.
- KETTLE: Generate XML ktr template files to be used by Kettle.
- DBLINK: 生成Oracle foreign data wrapper server to use as dblink.
- SYNONYM: Export Oracle's synonyms as views on other schema's objects.
- DIRECTORY: Export Oracle's directories as external_file extension objects.
- LOAD: Dispatch a list of queries over multiple PostgreSQl connections.
- TEST: perform a diff between Oracle and PostgreSQL database.
- TEST_VIEW: perform a count on both side of rows returned by views

Some export type can not or should not be load directly into the PostgreSQL database and still require little manual editing. This is the case for GRANT, TABLESPACE, TRIGGER, FUNCTION, PROCEDURE, TYPE, QUERY and PACKAGE export types especially if you have PLSQL code or Oracle specific SQL in it.



2. 生成sql文件

```Bash
ora2pg -c ora2pg.conf
```
