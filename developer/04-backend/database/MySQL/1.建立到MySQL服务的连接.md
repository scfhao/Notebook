4.2.2 建立到 MySQL 服务器的连接

如果无法建立连接，查看[Section 6.2.7, Troubleshooting Problems Connecting to MySQL](http://dev.mysql.com/doc/refman/5.5/en/problems-connecting.html).

一个可以连接到 MySQL 服务器的客户端程序，必须使用适当的连接参数，例如运行服务器的主机名和你的 MySQL 账户的用户名及密码，每个连接参数都有一个默认值，但在必要时可以使用命令行获可选文件选项来覆盖这些参数。

这里使用 mysql 客户端程序作为示例，但其原理也应用于其他客户端如 mysqldump、mysqladmin 或 mysqlshow。

不带任何连接参数来调用 mysql

```
shell> mysql
```

没有参数选项时使用的默认值：

* 默认的主机名是 localhost。在 Unix 上，它有特殊含义，稍后再叙。
* 默认的用户名在Windows上为ODBC，在Unix上为你在Unix上的登录名。
* 如果没有指定`-p`或`--password`，不发送密码。
* 对于mysql，第一个非选项参数作为默认数据库的名称。 如果没有这样的选项，mysql不选择默认数据库。

要显式指定主机名、用户名和密码，在命令行中提供相应的选项：

```
shell> mysql --host=localhost --user=myname --password=mypass mydb
shell> mysql -h localhost -u myname -pmypass mydb
```

对于密码选项，密码值是可选的：

* 如果你使用了`-p`或`--password`选项并指定了密码值，那么在`-p`或`--password=`和其后的密码之间不能有空格。
* 如果你使用了`-p`或`--password`选项并没有指定密码值，客户端程序会提示你输入密码。这样输入密码时密码不会显示在屏幕上，这种方式比在命令中给出密码更加安全。

MySQL内部不会限制密码的长度，但一些系统可能会提示密码必须小于8位字符，遇到这种情况时，可以设置一个小于8位的密码或将密码放在一个可选文件中来绕过这个问题。

在Unix上，MySQL程序特别处理主机名localhost，其方式可能与其他基于网络的程序相比有所不同。 对于到localhost的连接，MySQL程序尝试使用Unix套接字文件连接到本地服务器。 即使指定了`--port`或`-P`选项来指定端口号，也会发生这种情况。 要确保客户端与本地服务器建立TCP/IP连接，请使用`--host`或`-h`指定主机名值`127.0.0.1`或本地服务器的IP地址或名称。 您还可以通过使用`--protocol = TC`P选项显式指定连接协议（即使对于localhost）。 例如：

```
shell> mysql --host=127.0.0.1
shell> mysql --protocol=TCP
```

--protocol选项使您能够建立特定类型的连接，即使其他选项通常默认为某些其他协议。

如果服务器配置为接受IPv6连接，客户端可以使用--host = :: 1通过IPv6连接。 请参见[第5.1.9节“IPv6支持”](http://dev.mysql.com/doc/refman/5.5/en/ipv6-support.html)。

在Windows上，您可以通过指定--pipe或--protocol = PIPE选项或通过指定来强制MySQL客户端使用命名管道连接。 （句号）作为主机名。 如果未启用命名管道连接，则会发生错误。 如果不想使用默认管道名称，请使用--socket选项指定管道的名称。

与远程服务器的连接始终使用TCP / IP。 此命令使用默认端口号（3306）连接到在remote.example.com上运行的服务器：

```
shell> mysql --host=remote.example.com
```

要显式指定端口号，请使用--port或-P选项：

```
shell> mysql --host=remote.example.com --port=13306
```

您也可以为与本地服务器的连接指定端口号。 但是，如前所述，在Unix上的localhost的连接默认使用套接字文件。 您将需要强制执行已描述的TCP / IP连接，否则指定端口号的任何选项将被忽略。
