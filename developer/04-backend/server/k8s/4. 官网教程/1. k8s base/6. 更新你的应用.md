## 执行滚动更新

用户希望应用程序始终可用，而开发人员则需要每天多次部署它们的新版本。在Kubernetes 中，这些是通过滚动更新完成的。滚动更新允许通过使用新的实例逐步更新 Pod 实例，零停机进行 Deployment 更新。新的 Pod 将在具有可用资源的节点上进行调度。

在前面的模块中，我们将应用程序扩展为运行多个实例。这是在不影响应用程序可用性的情况下执行更新的要求。默认情况下，更新期间不可用的 Pod 的最大值和可用创建的新 Pod 数都是1。这两个选项都可以配置为（pod）数字或百分比。在 Kubernetes 中，更新是经过版本控制的，任何 Deployment 更新都可以恢复到以前的（稳定）版本。

与应用程序扩展类似，如果 Deployment 是公开的，服务将在更新期间仅对可用的 Pod 进行负载均衡。可用 Pod 是应用程序用户可用的实例。

滚动更新允许以下操作：

* 将应用程序从一个环境提升到另一个环境（通过容器镜像更新）
* 回滚到以前的版本
* 持续集成和持续交付应用程序，无需停机

## 交互式教程

### 更新应用程序的版本

要更新应用的镜像到版本2，使用`set image`命令，跟上 deployment 名称和新镜像版本：

```SHELL
kubectl set image deployments/kubernetes-bootcamp kubernetes-bootcamp=jocatalin/kubernetes-bootcamp:v2
```

这个命令通知 Deployment 去为应用使用一个不同的镜像并启动滚动更新。

### 检查更新

你也可以通过运行`rollout status`命令来确认更新：

```SHELL
kubectl rollout status deployments/kubernetes-bootcamp
```

### 回滚更新

让我们现在执行另一个更新，部署标签为`v10`的镜像：

```SHELL
kubectl set image deployments/kubernetes-bootcamp kubernetes-bootcamp=gcr.io/google-samples/kubernetes-bootcamp:v10
```

使用`get deployments`查看 deployment 的状态：

```SHELL
kubectl get deployments
```

注意输出中并没有列出期望的可用 Pods 数量。运行`get pods`命令列出所有的 pods：

```SHELL
kubectl get pods
```

注意状态为`ImagePullBackOff`的 Pods。

为了获取这个问题的更多信息，运行`describe pods`命令：

```SHELL
kubectl describe pods
```

在相关 pods 的 Events 部分，注意`v10`版本的镜像在仓库中不存在。

要回滚部署到之前的工作版本，使用`rollout undo`命令：

```SHELL
kubectl rollout undo deployments/kubernetes-bootcamp
```

你可以回退到之前任何已知状态部署。
