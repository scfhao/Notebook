使用 Composer 从头创建一个新项目

```
$ composer create-project -s dev zendframework/skeleton-application path/to/install
```

这将安装初始的依赖关系，包括：

* zend-component-installer，它有助于将组件配置自动注入到应用程序中。
* zend-mvc是MVC应用程序的内核。

默认值是提供运行zend-mvc应用程序所需的最小依赖关系。 但是，您可能会在开头就知道其他需求，因此，该骨架还附带一个安装程序插件，将提示您输入一些项目。

首先会提示：

```
Do you want a minimal install (no optional packages)? Y/n
```

> 提示和默认值
> 安装程序发出的所有提示都提供可用选项列表，并通过大写字母指定默认选项。 如果用户按“Enter”，没有任何值，则使用默认值。 在前面的例子中，“Y”是默认值。

如果您回答“Y”，或者不选择按Enter键，安装程序将不再提出任何其他提示，并完成安装应用程序。 如果你回答“n”，它会继续提示你：

```

```

开发人员工具栏提供了一个浏览器工具栏中的时间和分析信息，并且在调试应用程序时非常有用。 但是，为了本教程的目的，我们不会使用它; 点击“Enter”或“n”，然后按“Enter”。

```
Would you like to install caching support? y/N
```

我们不会在本教程中展示缓存，因此请点击“Enter”或“n”，然后点击“Enter”。

```

```

## 下载骨架
安装ZendSkeletonApplication的另一种方法是使用github来下载压缩的归档文件。 转到https://github.com/zendframework/ZendSkeletonApplication，单击“克隆或下载”按钮，然后选择“下载ZIP”。 这将下载一个名称为ZendSkeletonApplication-master.zip或类似的文件。

将该文件解压到保存所有vhost的目录中，并将生成的目录重命名为zf-tutorial。

ZendSkeletonApplication设置为使用Composer来解析它的依赖关系。 在新的zf-tutorial文件夹中运行以下命令来安装它们：

```
$ composer self-update
$ composer install
```

这需要一段时间 你应该看到如下输出：

```
Installing dependencies from lock file
- Installing zendframework/zend-component-installer (0.2.0)

...

Generating autoload files
```

此时，系统会提示您回答上述问题。

或者，如果您没有安装Composer，但是可以使用Vagrant或Docker-compose，则可以通过以下方式运行Composer：

```
# For Vagrant:
$ vagrant up
$ vagrant ssh -c 'composer install'
# For docker-compose:
$ docker-compose build
$ docker-compose run zf composer install
```

## 超时

如果你看到这个消息：

```
[RuntimeException]
The process timed out.
```

那么您的连接速度太慢，无法及时下载整个软件包，并且作曲家超时。 为了避免这种情况，而不是运行：

```
$ composer install
```

相反：

```
$ COMPOSER_PROCESS_TIMEOUT=5000 composer install
```

## Web服务器

在本教程中，我们将介绍四种不同的方式来设置Web服务器：

* 通过PHP内置的Web服务器。
* 通过Vagrant。
* 通过docker-compose.
* 使用 Apache。

### 使用PHP内置的Web服务器

开发应用程序时，可以使用PHP的内置Web服务器。 为此，从项目的根目录启动服务器：

```
$ php -S 0.0.0.0:8080 -t public public/index.php
```

这将使网站在所有网络接口上的端口8080上可用，使用public/index.php来处理路由。 这意味着可以通过http://localhost:8080或http://<your-local-IP>:8080访问该站点。

如果你这样做的话，你应该看到一个 Zend Framework 的欢迎页面。

要测试您的路由是否正常工作，请导航到http://localhost:8080/1234，您应该看到404页面.

> PHP的内置Web服务器只能用于开发。

### 使用 Vagrant

Vagrant提供了一种描述和配置虚拟机的方式，是为开发团队提供连贯一致的开发环境的常用方式。 骨架应用程序提供基于Ubuntu 14.04的Vagrantfile，并使用ondrej / php PPA提供PHP 7.0。 启动使用：

```
$ vagrant up
```

一旦构建并运行，您也可以从虚拟机运行 composer。 例如，以下将安装依赖关系：

```
$ vagrant ssh -c 'composer install'
```

而这会更新他们：

```
$ vagrant ssh -c 'composer update'
```

该映像使用Apache 2.4，并将主机端口8080映射到虚拟机上的端口80。

### 使用 docker-compose

Docker容器包装一个软件和运行所需的一切软件，保证一致的操作，而不管主机环境如何; 它是虚拟机的替代品，因为它作为主机环境之上的层运行。

docker-compose是用于自动化容器配置并组合它们之间的依赖关系的工具，如卷存储，网络等。

骨架应用程序附带Docker文件和docker-compose的配置; 我们建议使用docker-compose，因为它为您可能需要作为应用程序一部分的其他容器（包括数据库服务器，缓存服务器等）提供基础。 要构建和启动图像，请使用：

```
$ docker-compose up -d --build
```

第一次构建之后，您可以将其截断为：

```
$ docker-compose up -d
```

一旦构建，您还可以在容器上运行命令。 docker-compose配置最初只定义一个容器，环境名称为“zf”; 使用它来执行命令，例如通过 composer 更新依赖关系：

```
$ docker-compose run zf composer update
```

该配置包括PHP 7.0和Apache 2.4，并将主机端口8080映射到容器的端口80。

### 使用 Apache Web 服务器

我们不会覆盖安装Apache，并且假设您已经安装了Apache。 我们建议安装Apache 2.4，并且仅覆盖该版本的配置。

您现在需要为应用程序创建Apache虚拟主机并编辑您的主机文件，以便http://zf-tutorial.localhost将从zf-tutorial/public/目录提供index.php。

设置虚拟主机通常在httpd.conf或extra/httpd-vhosts.conf中完成。 如果您使用httpd-vhosts.conf，请确保您的主httpd.conf文件包含此文件。 一些Linux发行版（例如：Ubuntu）包Apache，以便配置文件存储在/etc/apache2中，并在/etc/apache2/sites-enabled文件夹内的每个虚拟主机上创建一个文件。 在这种情况下，您将将虚拟主机块放在/etc/apache2/sites-enabled/zf-tutorial文件中。

确保NameVirtualHost被定义并设置为*：80或类似的，然后定义一个这样的虚拟主机：

```
<VirtualHost *:80>
    ServerName zf-tutorial.localhost
    DocumentRoot /path/to/zf-tutorial/public
    SetEnv APPLICATION_ENV "development"
    <Directory /path/to/zf-tutorial/public>
        DirectoryIndex index.php
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>
```

确保更新您的/etc/hosts或c:\windows\system32\drivers\etc\hosts文件，以便zf-tutorial.localhost映射到127.0.0.1。 然后可以使用http://zf-tutorial.localhost访问该网站。

```
127.0.0.1 zf-tutorial.localhost localhost
```

重启 Apache.

要测试您的.htaccess文件是否正常工作，请导航到http://zf-tutorial.localhost/1234，您应该看到前面提到的404页面。 如果您看到标准的Apache 404错误，则需要在继续之前修复.htaccess用法。

如果您正在使用IIS与URL重写模块，请导入以下内容：

```
RewriteCond %{REQUEST_FILENAME} !-f
RewriteRule ^ index.php [NC,L]
```

您现在有一个工作的骨架应用程序，我们可以开始添加我们的应用程序的细节。

## 错误报告

或者，当使用Apache时，您可以使用VirtualHost中的APPLICATION_ENV设置让PHP将其所有错误输出到浏览器。 这在开发应用程序时可能很有用。

编辑zf-tutorial/public/index.php目录并将其更改为以下内容：

```
<?php

use Zend\Mvc\Application;

/**
* Display all errors when APPLICATION_ENV is development.
*/
if ($_SERVER['APPLICATION_ENV'] === 'development') {
error_reporting(E_ALL);
ini_set("display_errors", 1);
}

/**
* This makes our life easier when dealing with paths. Everything is relative
* to the application root now.
*/
chdir(dirname(__DIR__));

// Decline static file requests back to the PHP built-in webserver
if (php_sapi_name() === 'cli-server') {
$path = realpath(__DIR__ . parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH));
if (__FILE__ !== $path && is_file($path)) {
return false;
}
unset($path);
}

// Composer autoloading
include __DIR__ . '/../vendor/autoload.php';

if (! class_exists(Application::class)) {
throw new RuntimeException(
"Unable to load application.\n"
. "- Type `composer install` if you are developing locally.\n"
. "- Type `vagrant ssh -c 'composer install'` if you are using Vagrant.\n"
. "- Type `docker-compose run zf composer install` if you are using Docker.\n"
);
}

// Retrieve configuration
$appConfig = require __DIR__ . '/../config/application.config.php';
if (file_exists(__DIR__ . '/../config/development.config.php')) {
$appConfig = ArrayUtils::merge($appConfig, require __DIR__ . '/../config/development.config.php');
}

// Run the application!
Application::init($appConfig)->run();
```

## 开发模式

在开始之前，我们将为应用程序启用开发模式。 框架应用程序提供了两个文件，允许我们指定我们要在任何地方使用的一般开发设置; 这些可能包括启用模块进行调试或启用我们视图脚本中的错误显示。 这些文件位于：

* config/development.config.php.dist
* config/autoload/development.local.php.dist

当我们启用开发模式时，这些文件被复制到：

* config/development.config.php
* config/autoload/development.local.php

这使得它们可以合并到我们的应用程序中。 当我们禁用开发模式时，创建的这两个文件被删除，只留下.dist版本。 （存储库还包含忽略副本的规则。）

现在让我们启用开发模式：

```
$ composer development-enable
```

切勿在生产中实现开发模式

您不应该在生产中启用开发模式，因为启用它的典型原因是启用调试！ 如上所述，通过启用开发模式生成的工件不能提交到您的存储库，因此假设您不在生产中运行命令，则应该是安全的。

您可以使用以下方式测试开发模式的状态：

```
$ composer development-status
```

您可以使用以下命令禁用它：

```
$ composer development-disable
```
