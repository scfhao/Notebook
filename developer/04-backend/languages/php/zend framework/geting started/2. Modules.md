# 模块

zend-mvc使用模块系统来组织每个模块中的主要应用程序特定代码。 由骨架提供的应用程序模块用于向整个应用程序提供引导，错误和路由配置。 它通常用于为应用程序的主页提供应用程序级别控制器，但是我们不会使用本教程中提供的默认设置，因为我们希望将我们的专辑列表作为主页，它将存储在我们自己的模块中。

我们将把我们的所有代码放入专辑模块中，该模块将包含我们的控制器，模型，表单和视图以及配置。 我们还将根据需要调整应用程序模块。

我们从需要的目录开始吧。

## 设置专辑模块

首先创建一个名为Album的模块下面的目录，其中包含以下子目录来保存模块的文件：

```
zf-tutorial/
    /module
        /Album
            /config
            /src
                /Controller
                /Form
                /Model
            /view
                /album
                    /album
```

专辑模组有不同类型的文件，我们将拥有单独的目录。 包含Album名称空间中的类的PHP文件位于src /目录中。 视图目录还有一个子文件夹，称为相册，用于我们模块的视图脚本。

为了加载和配置一个模块，Zend Framework提供了一个ModuleManager。 这将在指定的模块命名空间（即Album）中寻找一个Module类; 在我们的新模块的情况下，这意味着类Album\Module，它将在模块/Album/src/Module.php中找到。

现在让我们创建这个文件，内容如下：

```
namespace Album;

use Zend\ModuleManager\Feature\ConfigProviderInterface;

class Module implements ConfigProviderInterface
{
    public function getConfig()
    {
        return include __DIR__ . '/../config/module.config.php';
    }
}
```

ModuleManager会自动为我们调用getConfig()。

### 自动加载

虽然Zend Framework通过zend-loader组件提供自动加载功能，但我们建议您使用Composer的自动加载功能。 因此，我们需要通知 Composer 我们的新命名空间及其文件的位置。

在您的项目根目录中打开composer.json，并查找自动加载部分; 默认情况下应该如下所示：

```
"autoload": {
    "psr-4": {
        "Application\\": "module/Application/src/"
    }
},
```

现在我们将新的模块添加到列表中，现在显示为：

```
"autoload": {
    "psr-4": {
        "Application\\": "module/Application/src/",
        "Album\\": "module/Album/src/"
    }
},
```

完成更改后，请运行以下操作，以确保Composer更新其自动加载规则：

```
$ composer dump-autoload
```

## 配置

注册了自动装载机后，我们快速浏览Album \ Module中的getConfig（）方法。 此方法将在模块的根目录下加载config / module.config.php文件。

在zf-tutorial / module / Album / config /下创建一个名为module.config.php的文件：

```
namespace Album;

use Zend\ServiceManager\Factory\InvokableFactory;

return [
    'controllers' => [
        'factories' => [
            Controller\AlbumController::class => InvokableFactory::class,
        ],
    ],
    'view_manager' => [
        'template_path_stack' => [
            'album' => __DIR__ . '/../view',
        ],
    ],
];
```

配置信息由ServiceManager传递给相关组件。 我们需要两个初始部分：控制器和view_manager。 控制器部分提供了由模块提供的所有控制器的列表。 我们需要一个控制器AlbumController; 我们将引用它的完全限定的类名，并使用zend-servicemanager InvokableFactory来创建它的实例。

在view_manager部分中，我们将视图目录添加到TemplatePathStack配置中。 这将允许它找到存储在我们的视图/目录中的专辑模块的视图脚本。

## 通知应用程序关于我们的新模块

我们现在需要告诉ModuleManager这个新的模块。 这是在应用程序的config / modules.config.php文件中完成的，该文件由骨架应用程序提供。 更新此文件，使其返回的数组也包含Album模块，因此该文件现在如下所示：

（需要更改使用注释突出显示;为简洁起见，省略了文件的原始注释。）

```
return [
    'Zend\Form',
    'Zend\Db',
    'Zend\Router',
    'Zend\Validator',
    'Application',
    'Album',          // <-- Add this line
];
```

如您所见，我们已将我们的相册模块添加到应用程序模块之后的模块列表中。

我们现在已经设置了可以将我们的自定义代码放入其中的模块。
