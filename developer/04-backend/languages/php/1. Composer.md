# Composer

[官网](https://getcomposer.org/)

Composer 是 PHP 中的依赖管理。

## 在 macOS 系统上安装

Composer 提供了一个可以很方便的在命令行运行的安装器，而且它是用纯 PHP 写的，[下载](https://getcomposer.org/installer) [GitHub](https://github.com/composer/getcomposer.org/blob/master/web/installer)。

安装 Composer 有两种方式，一种是作为你项目中的一部分，或者作为系统范围可执行的全局安装。

### 作为项目中的一部分

在项目本地安装只需要在项目目录下运行安装器就行了。

```
// 这里的 installer 就是上一步下载的安装器
php installer
```

安装器会检查几处 PHP 设置然后下载`composer.phar`到你的工作目录。这个文件是 Composer 的二进制文件，它是 PHAR 格式的，这是 PHP 的可以在命令行运行的归档格式。

然后执行`php composer.phar`来运行 Composer。

在运行安装器的时候，还可以通过`--install-dir`参数来指定目录，或通过`--filename`参数来修改名称，例如：

```
php composer-setup.php --install-dir=bin --filename=composer
```

这样，你就可以通过执行`php bin/composer`来运行 Composer 了。

### 全局安装

只要把 Composer 的 PHAR 文件放到设置到`PATH`中的目录下，你就可以全局的访问它了。在类 Unix 系统上，你甚至可以不直接使用 php 解释器来调用它。

这样你就可以运行`composer`来代替运行`php composer.phar`了。

## 基本使用

要在你的项目中使用 Composer，需要的仅是一个`composer.json`文件，这个文件描述了你的项目的依赖或其他元数据。这个文件不需要自己手动创建，可以查看后面关于 Composer 命令的部分。

### `require`键

在`composer.json`文件中首先需要指定的，通常也是仅需要指定的就是`require`键。简单的告诉 Composer 你的项目基于哪些包。

```
{
    "require": {
        "monolog/monolog": "1.0.*"
    }
}
```

如你所见，`require`接收一个从包名称到版本约束的映射。

Composer 使用这个信息从使用`repositories`键注册的或默认的 Packagist 包仓库中寻找正确的文件集合。

### 包名称

包名称由供应商名称和项目名称组成。

### 包版本约束

在我们的示例中，我们使用版本约束`1.0.*`来请求 Monolog 包，代表大于等于1.0并且小于1.0的版本。

Composer 查找包的时候会先从`repositories`注册的仓库中查找，找不到会在 Packagist 中查找。

### 安装依赖

运行`install`命令就可以为你的项目安装定义的依赖了。

```
php composer.phar install
```

### 更新依赖

```
php composer.phar update
php composer.phar update monolog/monolog
```
