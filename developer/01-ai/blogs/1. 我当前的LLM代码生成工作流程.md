## 全新项目

对全新项目，这套流程既能产出完备文档，又便于小步迭代。

### 第一步：打磨想法

用对话式 LLM 把创意细化（我用 ChatGPT 4o / o3）：

```
请一次只问我一个问题，这样我们可以为这个想法逐步制定出详尽的规划。每个问题都应基于我之前的回答逐步深入，最终目标是形成一份详细的方案，以便交付给开发人员。让我们循序渐进地探讨每个相关细节。记住，一次只问一个问题。

这是 idea:

<IDEA>
```

等头脑风暴自然收束后：

```
既然头脑风暴已经完成，您能否将我们的讨论结果整理成一份全面的、可供开发人员直接使用的规范文档？请包含所有相关需求、架构选择、数据处理细节、错误处理策略以及测试计划，以便开发人员可以立即开始实施。
```

模型会生成一份相当扎实的规范文档，我通常保存为`spec.md`。

> 这份规范不只用来代码生成。我常让推理模型“must go deeper!”——挑毛病、写白皮书、生成商业模型，甚至做深度研究，一口气回你一万字。

### 第二步：规划

把`spec.md`交给推理能力更强的模型（o1*、o3*、r1）。

（TDD 版提示词）

```
起草一份详细的、分步的项目构建蓝图。在制定出可靠计划后，将其分解为相互关联的小型迭代模块。审视这些模块，并进一步将其拆分为更细化的步骤。检查分解结果，确保每个步骤的粒度足够小，以便通过充分测试安全地实现，同时又足够实质性地推动项目进展。不断迭代，直至这些步骤的规模符合本项目的最佳实施尺度。

基于此，你应能构建一套面向代码生成大模型的提示词序列，使其能够以测试驱动的方式实现每个步骤。务必优先考虑最佳实践、渐进式推进和早期测试，确保任何阶段都不会出现复杂度的跃升。每一条提示词都需建立在前一条的基础上，并以代码集成收尾，确保不存在未与前期步骤衔接的孤立代码。

请务必划分每个提示词章节，使用Markdown格式。每条提示词需用代码标签标注为文本。最终目标是输出提示词，但相关上下文等内容也同样重要。

<SPEC>
```

（非 TDD 版提示词）

```
起草一份详细的分步项目构建蓝图。制定可靠计划后，将其分解为若干相互关联的小型迭代模块。审视这些模块，并进一步拆分为更细化的步骤。检查分解结果，确保每个步骤的粒度既能通过充分测试安全实现，又能实质性地推动项目进展。持续迭代，直至步骤规模符合本项目的最佳实施要求。

基于此，您应能构建一套面向代码生成大模型的提示词序列，用于分步实现每个环节。务必遵循最佳实践，采用渐进式推进策略，确保每个阶段都不会出现复杂度跃升。每条提示词都需承前启后，最终实现代码集成，确保不存在任何未与前期步骤衔接的孤立代码。

请用Markdown格式划分每个提示词章节。每条提示词需使用代码标签标注为文本。最终目标是输出提示词，但相关上下文等内容也需一并保留。

<SPEC>
```

模型会产出一份可直接执行的提示词清单，我保存为`prompt_plan.md`。

接着让它生成勾选清单`todo.md`：

```
你能否制作一份详细的 todo.md 文件，作为我的核对清单？请务必全面详尽。
```

> 最好让代码生成工具在执行时自动勾选`todo.md`，这样跨会话也能保持进度。

### 步骤三：执行

#### Claude

我把 claude.ai 当结对伙伴，逐条投喂提示词，虽来回沟通略多，但整体可靠。

仓库初始化和工具链由我先搭好，避免 Claude 一股脑吐 React 代码。卡住时，我会用 repomix 打包完整代码库让 Claude 调试。

流程大致如下：

* 初始化仓库（样板代码、`uv init`、`cargo init`等）
* 把提示词粘给 Claude
* 将 Claude 输出复制到 IDE
* 运行代码或测试
* 如果通过，继续下一个提示词
* 如果未通过，用 repomix 打包代码让 Claude 调试
* 重复 ✩₊˚.⋆☾⋆⁺₊✧

#### Aider

Aider 上手有点奇特，但与第二步产出的提示词配合得天衣无缝，能极省心地推进。

Aider 的流程与上面几乎一致，只是把提示词粘到 Aider 而非 Claude，而且 Aider 会自动修改文件、执行命令并汇报结果。

流程如下：

* 初始化仓库（样板代码、`uv init`、`cargo init`等）
* 启动 aider
* 粘入提示词
* 观看 aider “跳舞” ♪┏(・o･)┛♪
* Aider 会自动运行测试；也可手动验证
* 如果通过，继续下一个提示词
* 如果未通过，与 Aider 问答修复
* 重复 ✩₊˚.⋆☾⋆⁺₊✧
