## 快速开始

### 提示基础

1. 说出你希望事情如何完成，而不仅仅是说出要做什么

可以将这个智能体视为一名初级编程搭档，其决策过程可能不太可靠。简单的任务可以直接描述，但对于更复杂的任务，请从一开始就清晰说明你偏好的解决方法。提前为智能体提供整体架构和逻辑，不仅能提高它完成任务的成功率，还能减少你审查代码的时间，因为你会对预期的实现方法早已心中有数。

2. 告诉智能体从哪里开始

想想如果你亲自处理这项任务，会从哪里入手。即便你不知道具体的文件或函数名称，也要提及涉及的代码仓库、相关文档和关键组件。明确标注这些要素，能最大程度减少无用功和混乱。

```示例：
“请在我们的代码中添加对 Google 模型的支持。你需要查看最新文档[此处](link)，并在模型组目录中创建一个新的实现文件”
```

3. 练习防御性提示

想象把同一个指令交给新的实习生。哪些地方很可能出现困惑或失误？提前预判这些要点，主动把说明讲清楚，避免表述模糊。

```示例：
“请修复我们搜索模块的C++绑定以通过新的单元测试。注意，你可能需要在每次修改代码后重新编译绑定，然后再进行测试。”
```

4. 授予对 CI、测试、类型和代码检查工具的访问权限

智能体的诸多神奇之处，源于它们能够纠正自身错误并根据错误提示不断迭代优化。通过类型检查器、代码检查工具和单元测试等工具构建完善的反馈循环，能极大提升它们的性能。建议优先使用带类型标注的 Python 替代纯 Python，或使用 TypeScript 替代 JavaScript。要教会智能体如何运行常见的检查和测试，确保它拥有所有必要的包和访问权限。如果智能体可以与浏览器交互，就为其提供清晰的指令，指导其运行前端开发环境。

5. 发挥你的专业能力

当你熟悉了自己的代码库，以上所有事情都会变得更轻松。即便只是简单的任务，你验证逻辑和结果的能力也能带来帮助。人工监督依然至关重要——归根结底，你要对代码的最终正确性负责。即便这些工具变得越来越先进，所有权和验证也将继续是人类工程师的核心职责。

### 工作流程

1. 立即接手新任务

想象一下有同事给你发消息说：“嘿，我们能快速做个X吗？”或者“我们需要调整一下Y。”与其让这些事打断你的工作节奏，只需向智能体快速发送指令，让其去调查或完成修改。这样你就能专注于核心任务了。

2. 随时随地编写代码

想象一下你在通勤或出行时，突然遇到一个紧急的程序漏洞，或者意识到自己可能在代码中留下了一个错误。别担心！智能体通常支持移动访问，让你能立即解决这些问题。无论是通过 Slack 移动应用还是专用的移动应用，许多智能体都能让你在路上处理问题，即便你的网络信号不稳定也没问题。

3. 把你的家务交给别人

还在为查找旧提交的二分问题或为新功能更新文档而陷入困境？把这些重复性任务交给你的智能体吧。你将节省宝贵时间，专注于更具创造性和影响力的工作。

4. 摆脱分析瘫痪

还在纠结重构是否真的能简化代码？无法在两种架构方案中做选择？让你的智能体同时实现这两种方案。有具体示例可供对比，决策过程会变得清晰明了，而且放弃某一方案也不会让任何人感到不适。

5. 设置预览部署

将你的 CI/CD 流水线设置为每次新建拉取请求（PR）时自动创建预览部署，这样你就能获得一个即时的在线访问链接。在审核由 AI 智能体完成的前端任务时，这一功能会格外实用。Vercel 是一个部署平台，能让预览部署变得非常简单。

## 中级

### 大型任务

1. 自动化你的初稿

对于大型任务，使用智能体来生成拉取请求（PR）的初稿可以推动项目进展，并大幅减少你的工作量。这一过程的成功取决于提前清晰地传达你的预期思路。你可以把自己想象成指导初级开发人员的架构师：清晰、具体的指令有助于避免浪费不必要的时间去纠正智能体代码中存在的根本性误解。

记住，大型任务目前还无法完全实现全自动处理。对于难度较高的任务，需要经历多次反馈循环；若要达到精致的效果，还需进行一些手动优化。一个现实的目标是节省约80%的时间，而非实现完全自动化，你的专业经验对于验证和最终的质量保障依然至关重要。

2. 共同制定产品需求文档

对于复杂或定义模糊的任务，与你的智能体协作制定详细计划会非常有效。某些智能体（如 Devin 和 Claude Code）提供专门的规划模式，这类模式侧重于阅读和探究现有代码，而非立即对其进行修改。

3. 设置检查点

对于多部分任务，尤其是涉及多个代码库的任务，需在过程中设定明确的检查点：

```示例：
规划 → 实现模块 → 测试 → 修复 → 检查点评审 → 下一个模块
```

在每个重要阶段结束后明确要求暂停，尤其是针对跨多个层级（例如数据库、后端、前端）构建的复杂功能。利用这些检查点确保实现符合你的预期，厘清疑问（例如“解释授权流程并确认其安全性”），并尽早调整方向以避免连锁问题。

```示例：
“我希望你实现这个功能，该功能将涉及我们的数据库、后端和多个前端界面。请首先规划出所需的数据库架构变更，完成后告知我，以便我应用迁移。”→“现在请实现后端变更并添加测试，确保 XYZ 功能正常。完成后告知我。”→“现在在我们的网页和移动界面中实现变更，以调用新的后端端点。”
```

4. 教它验证自己的工作

提供反馈时，不要只简单指出问题（“这个功能无法正常工作”）。清晰说明你的测试流程，以便智能体能够独立验证未来的任务。对于你会频繁使用的测试模式，将其整合到智能体的永久知识库中。

5. 提高AI高频修改区域的测试覆盖率

目前，智能体还无法完全有能力全面地交互式测试所有场景。在被AI大量修改的区域提高测试覆盖率，能让人们对智能体的输出更有信心。完善的测试意味着，看似正确的代码可以放心地合并，无需担忧。

## 高级

### 自动化

1. 为你最重复的工作创建快捷方式

工程团队经常会遇到重复性的常规工作。这些工作非常适合通过智能体实现自动化。常见的例子包括：

* feature flag removal 功能标志移除
* 依赖项升级
* 在新功能PR中修复并补充测试

为了高效地完成这项设置，经验丰富的工程师通常会创建一个可靠且可重复使用的提示模板。可针对这些场景反复运行。

2. 智能代码审查与合规执行

3. 关联事件与警报

在对生产环境中的问题进行分类处理时，人工智能的调试能力并没有那么出色。与其让人工智能在问题出现时从头到尾修复漏洞，不如让它只标记出最可疑的错误、变更等内容，这种做法往往更实际可行。

### 自定义

1. 环境设置

```示例：
我们为智能体的浏览器设置了预认证登录，省去了手动认证的麻烦，也让测试变得更加便捷。
```

2. 构建自定义命令行界面工具和消息处理程序

示例：我们有一位客户，他们开发了一款 CLI 工具并取得了显著成效，该工具仅展示测试套件中第一个失败的测试。这个 CLI 会提示智能体只关注该测试，并提供详细的错误信息，这使得智能体在处理长任务时成功率更高、完成速度更快。

3. 添加到你的智能体的知识库

如果你的智能体出现了一些常见错误，这正是将你的反馈整理到智能体知识库中的好时机。许多产品会提供.rules 文件和.md 文件，供智能体永久吸收。你不仅要向它说明你所使用的框架的相关准则，还要告诉它你项目的整体架构、不同类型任务常用的测试类型、重要命令的执行方式，以及你推荐使用的工具。

## 实际考量

### 局限性

1. 调试能力有限
2. 细粒度视觉推理能力差

如今的模型通常不具备匹配设计截图或 Figma 原型所需细节级别的视觉推理能力。

3. 知识截止点

### 成本管理

并非每次使用智能体都能获得成功。2025年，这些智能体的实际结果存在着不小的差异。这项工作的一部分，就是学会如何运用智能体，以最大程度地获得成功结果，同时尽量减少时间和令牌的浪费。

1. 愿意更早止损

刚接触智能体的人常犯的一个错误是，即便智能体的工作偏离了正轨，仍执意要让一次交互取得成功。如果你发现自己心里想着“它无视我的指令”或是“这东西一直在原地打转”，那么终止这段对话或手动接管操作是完全没问题的。发送更多消息，往往意味着你的任务本身的复杂程度超出了智能体的能力范围，而非只是某个能被纠正的简单错误。

2. 多样化你的实验
3. 当没有进展时重新开始

### 安全

1. 为你的智能体创建账户
2. 为其提供一个开发/测试环境
3. 只读API密钥

### 结论

我们坚信，软件工程师永远不会被取代。即便编码智能体变得愈发智能、能力更强，深厚的技术专业知识以及对代码库的深入了解依然价值连城。如今，对你的项目、系统和代码真正的掌控力，比以往任何时候都更为关键。在我们团队，工程师不仅需要深入理解并做出审慎判断，还得负责监管多个系统。随着自动化放大你的影响力，同时处理多项任务的能力不再只是一种可能，更会成为必备素质。我们很高兴能分享在推动自身组织适应这一转型过程中积累的经验见解，助力你和你的团队在不断发展的软件开发领域中蓬勃发展。
