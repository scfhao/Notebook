# 蜘蛛

蜘蛛是指定义了如何爬取确定的网站（或网站组），包含了如何爬取和如何从页面中取出结构化的数据的类。换句话说，蜘蛛是对特定的站点实现自定义的爬取和解析页面逻辑的地方。

对于蜘蛛来说，抓取周期是这样的：

1. 生成初始请求以抓取第一个 URL，从这些请求中下载响应后调用指定的回调函数。

要执行的第一个请求是通过调用`start_requests()`方法获得的，该方法（默认情况下）为`start_urls`中指定的 URL 生成`Request`，并将`parse`方法作为`Request`的回调函数。

2. 在回调函数中，将解析响应（网页）并返回数据项对象、`Request`对象或这些对象的可迭代器。这些请求也将包含一个回调函数（也许是相同的），然后 Scrapy 将下载这些请求，并由指定的回调函数处理它们的响应。

3. 在回调函数中，你通常使用选择器（也可以使用 BeautifulSoup、lxml 或其他你喜欢的机制）来解析页面内容，并用解析后的数据生成数据项。

4. 最后，从 spider 返回的项目通常会持久化到数据库（在某些[数据项 pipeline](https://docs.scrapy.org/en/latest/topics/item-pipeline.html#topics-item-pipeline)中）或使用[Feed exports](https://docs.scrapy.org/en/latest/topics/feed-exports.html#topics-feed-exports)写入文件。

尽管这个周期（或多或少）适用于任何类型的蜘蛛，但为了不同的目的，Scrapy 中捆绑了不同类型的默认蜘蛛。我们将在这里讨论这些类型。

## `scrapy.Spider`

这是最简单的蜘蛛，任何其他的蜘蛛都必须继承这个类（包括 Scrapy 中自带的蜘蛛和我们自己写的蜘蛛）。它不提供任何特殊的功能，只提供了一个`start_request()`方法的默认实现，从蜘蛛的`start_urls`属性拿到 URL 发送请求，并对各请求的响应结果调用蜘蛛的`parse`方法。

### `name`

定义蜘蛛名字的字符串。Scrapy 通过蜘蛛的名字来定位和实例化蜘蛛，所以这个名字必须是唯一的。然而，也没规定不能为一个蜘蛛创建多个实例。这个属性是必须写的。

如果蜘蛛只抓取一个域名，通常的做法是用域名来命名蜘蛛，不管有没有顶级域名。例如，抓取`mywebsite.com`的蜘蛛通常被称为`mywebsite`。

### `allowed_domains`

一个可选的字符串列表，包含允许该蜘蛛抓取的域名。如果启用了`OffsiteMiddleware`，不属于此列表中指定的域名（或其子域名）的 URL 请求将不会被跟踪。

假设您的目标网址是`https://www.example.com/1.html`，那么在列表中添加 "example.com"。

### `start_urls`

在未指定特定 URL 的情况下，蜘蛛将开始抓取的 URL 列表。因此，首先下载的网页将是此处列出的网页。随后的`Request`将根据起始 URL 中的数据陆续生成。

### `custom_settings`

一个设置字典，在运行此蜘蛛时将从项目配置中覆盖这些设置。由于设置会在实例化之前更新，因此必须将其定义为类属性。

有关可用内置设置的列表，请参阅：[内置设置参考](https://docs.scrapy.org/en/latest/topics/settings.html#topics-settings-ref)。

### `crawler`

在类初始化后，该属性由`from_crawler()`类方法设置，并链接至该 spider 实例所绑定的`Crawler`对象。

爬虫（Crawlers）在项目中封装了许多组建，以便于单一入口访问（如扩展、中间件、信号管理器等）。如需了解更多，请参阅[爬虫API](https://docs.scrapy.org/en/latest/topics/api.html#topics-api-crawler)。

### `settings`

运行该蜘蛛的配置。这是一个`Settings`实例，有关详细介绍，请参阅[Settings](https://docs.scrapy.org/en/latest/topics/settings.html#topics-settings)主题。

### `logger`

以 Spider 的`name`创建的 Python 日志记录器。你可以使用它来发送日志信息，如[Spider 的日志记录](https://docs.scrapy.org/en/latest/topics/logging.html#topics-logging-from-spiders)所述。

### `state`

您可以用它在不同批次(batches)之间持续保持某些蜘蛛状态。有关详情，请参阅[在批次间保持持久状态](https://docs.scrapy.org/en/latest/topics/jobs.html#topics-keeping-persistent-state-between-batches)。

### `from_crawler(crawler, *args, **kwargs)`

这是 Scrapy 用来创建蜘蛛的类方法。

你可能不需要直接重写它，因为默认实现代理到`__init__()`方法，使用给定参数`args`和命名参数`kwargs`调用它。

不过，该方法会在新实例中设置`crawler`和`settings`属性，以便以后在蜘蛛代码中访问它们。

2.11 版中的更改：爬虫设置`crawler.settings`中的设置现在可以在此方法中修改，这对于根据参数修改设置非常方便。因此，这些设置并不是最终值，因为它们可以在以后被附加组件等修改。出于同样的原因，大多数`Crawler`属性在此时都没有初始化。

最终的`settings`和初始化的`Crawler`属性可在`start_requests()`方法、engine_started 信号的处理程序及后续程序中使用。

参数说明：

* crawler(Crawler示例)-当前蜘蛛将绑定的爬虫
* args(list)-传递到`__init__()`方法的参数
* kwargs(dict)-传递到`__init__()`方法的关键字参数

### `classmethod update_settings(settings)`

`update_settings()`方法用于修改 spider 的设置，在初始化 spider 实例时被调用。

它以`Settings`对象为参数，可以添加或更新蜘蛛的配置值。该方法是一个类方法，即在蜘蛛类中调用，允许蜘蛛的所有实例共享相同的配置。

虽然可以在`custom_settings`中设置每个蜘蛛的`settings`，但使用`update_settings()`，可以根据其他设置、蜘蛛属性或其他因素动态添加、删除或更改设置，并使用`'spider'`以外的设置优先级。此外，在子类中通过重载`update_settings()`很容易进行扩展，而在`custom_settings`中做同样的事情却很难。

例如，假设蜘蛛需要修改`FEEDS`：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"
    custom_feed = {
        "/home/user/documents/items.json": {
            "format": "json",
            "indent": 4,
        }
    }

    @classmethod
    def update_settings(cls, settings):
        super().update_settings(settings)
        settings.setdefault("FEEDS", {}).update(cls.custom_feed)
```

### `start_requests()`

该方法必须返回一个迭代器，其中包含该蜘蛛要抓取的第一批请求。Scrapy 在打开蜘蛛进行抓取时会调用该方法。Scrapy 只调用一次，因此将`start_requests()`作为生成器来实现是安全的。

默认实现会为`start_urls`中的每个 url 生成`Request(url,dont_filter=True)`。

如果要更改用于启动域名抓取的请求，可以覆盖此方法。例如，如果需要使用 POST 请求登录，可以这样做：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"

    def start_requests(self):
        return [
            scrapy.FormRequest(
                "http://www.example.com/login",
                formdata={"user": "john", "pass": "secret"},
                callback=self.logged_in,
            )
        ]

    def logged_in(self, response):
        # here you would extract links to follow and return Requests for
        # each of them, with another callback
        pass
```

### `parse(response)`

当请求未指定回调时，这是 Scrapy 用来处理下载响应的默认回调。

`parse`方法负责处理响应，并返回刮擦数据和/或更多要跟踪的 URL。其他请求回调的要求与`Spider`类相同。

此方法以及任何其他请求回调都必须返回一个`Request`对象、一个[item对象](https://docs.scrapy.org/en/latest/topics/items.html#topics-items)、一个`Request`对象和/或 item 对象的可迭代器，或`None`。

參數：`response`-要解析的响应

### `log(message [, level, component])`

封装器，通过 Spider 的`logger`发送日志信息，向后兼容。更多信息，请参阅[从 Spider 获取日志](https://docs.scrapy.org/en/latest/topics/logging.html#topics-logging-from-spiders)。

### `closed(reason)`

蜘蛛关闭时调用。该方法为`spider_closed`信号提供了`signal.connect()`的快捷方式。

## Spider 参数

蜘蛛可以接收参数来修改自己的行为。蜘蛛参数的一些常见用途是定义起始 URL 或将抓取限制在网站的某些部分，但也可用于配置蜘蛛的任何功能。

Spider 参数通过`-a`选项传递给`crawl`命令。例如：

```SHELL
scrapy crawl myspider -a category=electronics
```

蜘蛛可以在它们的`__init__`方法中访问参数：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"

    def __init__(self, category=None, *args, **kwargs):
        super(MySpider, self).__init__(*args, **kwargs)
        self.start_urls = [f"http://www.example.com/categories/{category}"]
        # ...
```

默认的`__init__`方法会接收任何 spider 参数，并将它们作为属性复制到 spider 中。上面的示例也可以写成下面这样：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"

    def start_requests(self):
        yield scrapy.Request(f"http://www.example.com/categories/{self.category}")
```

如果[通过脚本运行 Scrapy](https://docs.scrapy.org/en/latest/topics/practices.html#run-from-script)，可以在调用`CrawlerProcess.crawl`或`CrawlerRunner.crawl`时指定蜘蛛参数：

```Python
process = CrawlerProcess()
process.crawl(MySpider, category="electronics")
```

请记住，蜘蛛参数只是字符串。spider 不会自行进行任何解析。如果要在命令行中设置`start_urls`属性，必须使用`ast.literal_eval()`或`json.loads()`等工具将其解析为一个列表，然后将其设置为属性。否则，就会对`start_urls`字符串进行迭代（这是 python 的一个常见陷阱），导致每个字符都被视为一个单独的 url。

一个有效的用例是设置`HttpAuthMiddleware`使用的 http auth 凭据或`UserAgentMiddleware`使用的用户代理：

```SHELL
scrapy crawl myspider -a http_user=myuser -a http_pass=mypassword -a user_agent=mybot
```

Spider 参数也可通过 Scrapyd`schedule.json`API 传递。请参阅[Scrapyd 文档](https://scrapyd.readthedocs.io/en/latest/)。

## 通用的蜘蛛

Scrapy 提供了一些有用的通用蜘蛛，你可以让你的蜘蛛作为他们的子类。它们的目的是为一些常见的抓取情况提供便捷的功能，例如根据特定规则跟踪网站上的所有链接、从 Sitemaps 抓取或解析 XML/CSV feed。

在下面的蜘蛛程序示例中，我们假定您有一个在`myproject.items`模块中声明了 `TestItem`的项目：

```Python
import scrapy

class TestItem(scrapy.Item):
    id = scrapy.Field()
    name = scrapy.Field()
    description = scrapy.Field()
```

### CrawlSpider

`class scrapy.spiders.CrawlSpider`

这是用于抓取常规网站的最常用蜘蛛，因为它通过定义一系列规则，为跟踪链接提供了一种方便的机制。它可能并不最适合你的特定网站或项目，但它的通用性足以应对多种情况，因此你可以从它开始，然后根据需要覆盖它以实现更多自定义功能，或者直接实现你自己的蜘蛛。

除了从 Spider 继承的属性（必须指定）外，该类还支持一个新属性：

* `roles`

是一个（或多个）规则对象的列表。每个规则都定义了抓取网站的特定行为。规则对象的描述如下。如果有多个规则与同一链接匹配，则将根据该属性中定义的顺序使用第一个规则。

该蜘蛛还暴露了一个可覆盖的方法：

* `parse_start_url(response, **kwargs)`

针对 spider 的 start_urls 属性中的 URL 生成的每个响应都会调用该方法。它允许解析初始响应，并必须返回一个 item 对象、一个 Request 对象或一个包含其中任何一个的可迭代对象。

#### 爬取规则

`class scrapy.spiders.Rule(link_extractor=None, callback=None, cb_kwargs=None, follow=None, process_links=None, process_request=None, errback=None)`

* `link_extractor`是一个链接提取器对象，用于定义如何从每个抓取页面中提取链接。生成的每个链接都将用于生成一个`Request`对象，该对象的`meta`字典（`link_text`关键字下）中将包含链接文本。如果省略，则将使用不带参数的默认链接提取器，从而提取所有链接。

* `callback`是一个可调用方法或字符串（在这种情况下，将使用 spider 对象中具有该名称的方法），用于调用使用指定链接提取器提取的每个链接。该回调接收一个 Response 作为第一个参数，并必须返回`item 对象`或`Request 对象`（或它们的任何子类）的单个对象或可迭代实例。如上所述，接收到的响应对象将在其`meta`字典（`link_text`关键字下）中包含产生请求的链接文本。

* `cb_kwargs`是一个 dict，包含要传递给回调函数的关键字参数。

* `follow`是一个布尔值，用于指定是否要跟踪使用此规则提取的每个响应中的链接。如果`callback`为空，则默认为`True`，否则默认为`False`。

* `process_links`是可调用的，或者是一个字符串（在这种情况下，将使用蜘蛛对象中具有该名称的方法），使用指定的`link_extractor`从每个响应中提取的每个链接列表都将被调用。这主要用于过滤目的。

* `process_request`是一个可调用方法（或一个字符串，在这种情况下，将使用蜘蛛对象中具有该名称的方法），该方法将被调用到此规则提取的每个请求。该可调用方法的第一个参数是上述请求，第二个参数是该请求的源响应。它必须返回`Request`对象或`None`（过滤掉请求）。

* `errback`是一个可调用方法或字符串（在这种情况下，将使用蜘蛛对象中具有该名称的方法），当处理规则生成的请求时出现异常，将调用该方法。它的第一个参数是一个`Twisted Failure`实例。

> 由于其内部实现的原因，在编写基于`CrawlSpider`的蜘蛛时，必须为新请求明确设置回调；否则可能会出现意外行为。

#### CrawlSpider 示例

现在让我们来看看带规则的 CrawlSpider 示例：

```Python
import scrapy
from scrapy.spiders import CrawlSpider, Rule
from scrapy.linkextractors import LinkExtractor

class MySpider(CrawlSpider):
    name = "example.com"
    allowed_domains = ["example.com"]
    start_urls = ["http://www.example.com"]

    rules = (
        # Extract links matching 'category.php' (but not matching 'subsection.php')
        # and follow links from them (since no callback means follow=True by default).
        Rule(LinkExtractor(allow=(r"category\.php",), deny=(r"subsection\.php",))),
        # Extract links matching 'item.php' and parse them with the spider's method parse_item
        Rule(LinkExtractor(allow=(r"item\.php",)), callback="parse_item"),
    )

    def parse_item(self, response):
        self.logger.info("Hi, this is an item page! %s", response.url)
        item = scrapy.Item()
        item["id"] = response.xpath('//td[@id="item_id"]/text()').re(r"ID: (\d+)")
        item["name"] = response.xpath('//td[@id="item_name"]/text()').get()
        item["description"] = response.xpath(
            '//td[@id="item_description"]/text()'
        ).get()
        item["link_text"] = response.meta["link_text"]
        url = response.xpath('//td[@id="additional_data"]/@href').get()
        return response.follow(
            url, self.parse_additional_page, cb_kwargs=dict(item=item)
        )

    def parse_additional_page(self, response, item):
        item["additional_data"] = response.xpath(
            '//p[@id="additional_data"]/text()'
        ).get()
        return item
```

该蜘蛛将开始抓取 example.com 的主页，收集类别链接和项目链接，并使用`parse_item`方法解析后者。对于每个 Item 响应，将使用 XPath 从 HTML 中提取一些数据，并将其填充到一个`Item`中。

### XMLFeedSpider

`class scrapy.spiders.XMLFeedSpider`

XMLFeedSpider 设计用于对某个节点名称来解析和迭代 XML feed。迭代器可选：`iternodes`、`xml`和`html`。出于性能考虑，建议使用 iternodes 迭代器，因为`xml`和`html`迭代器会一次性生成整个 DOM 树以进行解析。不过，使用`html`作为迭代器在解析标记不良的 XML 时可能会有用。

要设置迭代器和标签(tag)名，必须定义以下类属性：

* iterator

一个字符串，用于定义要使用的迭代器。可以是:

`iternodes`-基于正则表达式的快速迭代器

`html`-是一个使用`Selector`的迭代器。请记住，这使用的是 DOM 解析，必须在内存中加载所有 DOM，这对大型 feed 来说可能是个问题。

`xml`-是一个使用选择器的迭代器。请记住，这使用的是 DOM 解析，必须在内存中加载所有 DOM，这对大型 feed 来说可能是个问题。

它的默认值是：`iternodes`

* itertag

包含要迭代的节点（或元素）名称的字符串。例如

```Python
itertag = 'product'
```

* namespaces

`(prefix, uri)`元组的列表，其中定义了将被此 spider 处理的文档中可用的命名空间。`prefix`和`uri`将用于使用`register_namespace()`方法自动注册命名空间。

然后，您可以在`itertag`属性中指定带有命名空间的节点。

示例：

```Python
class YourSpider(XMLFeedSpider):

    namespaces = [('n', 'http://www.sitemaps.org/schemas/sitemap/0.9')]
    itertag = 'n:url'
    # ...
```

除了这些新属性外，该蜘蛛还具有以下可重载方法：

* adapt_response(response)

在蜘蛛开始解析响应之前，从蜘蛛中间件接收响应的方法。该方法可用于在解析响应之前修改响应正文。该方法接收一个响应并返回一个响应（可能是同一个响应，也可能是另一个响应）。

* parse_node(response, selector)

该方法用于调用与提供的标签名称（`itertag`）相匹配的节点。接收响应和选择器(作为参数)。必须重载此方法。否则，你的 spider 将无法工作。此方法必须返回一个 item 对象、一个 Request 对象或一个包含它们的可迭代对象。

* process_results(response, results)

蜘蛛返回每次结果（项目或请求）时都会调用该方法，目的是在将结果返回给框架核心之前执行所需的最后处理，例如设置 item ID。它接收结果列表和产生这些结果的响应。它必须返回一个结果（项目或请求）列表。

> 由于其内部实现的原因，在编写基于 XMLFeedSpider 的蜘蛛时，必须为新请求明确设置回调；否则会出现意外行为。

这些蜘蛛非常容易使用，让我们来看一个例子：

```Python
from scrapy.spiders import XMLFeedSpider
from myproject.items import TestItem

class MySpider(XMLFeedSpider):
    name = "example.com"
    allowed_domains = ["example.com"]
    start_urls = ["http://www.example.com/feed.xml"]
    iterator = "iternodes"  # This is actually unnecessary, since it's the default value
    itertag = "item"

    def parse_node(self, response, node):
        self.logger.info(
            "Hi, this is a <%s> node!: %s", self.itertag, "".join(node.getall())
        )

        item = TestItem()
        item["id"] = node.xpath("@id").get()
        item["name"] = node.xpath("name").get()
        item["description"] = node.xpath("description").get()
        return item
```

基本上，我们所做的就是创建一个蜘蛛，从给定的 start_urls 中下载一个 feed，然后遍历其中的每个 item 标签，打印出来，并将一些随机数据存储到一个`Item`中。

### CSVFeedSpider

`class scrapy.spiders.CSVFeedSpider`

这种蜘蛛与 XMLFeedSpider 非常相似，不同之处在于它迭代的是行，而不是节点。每次迭代调用的方法是`parse_row()`。

* `delimiter` 一个字符串，包含 CSV 文件中每个字段的分隔符 默认为","（逗号）。
* `quotechar` 一个字符串，包含 CSV 文件中每个字段的外壳字符 默认为'"'（引号）。
* `headers` CSV 文件中的列名列表。
* `parse_row(response, row)` 接收一个响应和一个 dict（代表每一行），其中包含 CSV 文件中每个提供（或检测到）的标头的`key`。该蜘蛛程序还提供了覆盖`adapt_response`和`process_results`方法的机会，以便进行预处理和后处理。

CSVFeedSpider 示例：

让我们来看一个与前面类似的例子，但使用的是 CSVFeedSpider：

```Python
from scrapy.spiders import CSVFeedSpider
from myproject.items import TestItem

class MySpider(CSVFeedSpider):
    name = "example.com"
    allowed_domains = ["example.com"]
    start_urls = ["http://www.example.com/feed.csv"]
    delimiter = ";"
    quotechar = "'"
    headers = ["id", "name", "description"]

    def parse_row(self, response, row):
        self.logger.info("Hi, this is a row!: %r", row)

        item = TestItem()
        item["id"] = row["id"]
        item["name"] = row["name"]
        item["description"] = row["description"]
        return item
```

### SitemapSpider

`class scrapy.spiders.SitemapSpider`

SitemapSpider 可让您使用[Sitemaps](https://www.sitemaps.org/index.html)发现 URL，从而抓取网站。

它支持嵌套网站地图和从[robots.txt](https://www.robotstxt.org/)中发现网站地图网址。

* `sitemap_urls`

指向您要抓取的网站地图网址的网址列表。

您也可以指向 robots.txt，然后对其进行解析，从中提取网站地图网址。

* `sitemap_rules`

元组（regex，回调）列表，其中：

`regex`是一个正则表达式(可以是一个字符串，也可以是正则表达式对象)，用于匹配从网站地图中提取的 url。

`callback`是用于处理与正则表达式匹配的 url 的回调。callback 可以是字符串（表示 spider 方法的名称），也可以是可调用的。

例如：

```Python
sitemap_rules = [('/product/', 'parse_product')]
```

规则是按顺序应用的，只有第一个匹配的规则才会被使用。

如果省略此属性，将使用解析回调处理在网站地图中找到的所有 url。

* `sitemap_follow`

应跟踪的网站地图正则表达式 列表。仅适用于使用指向其他网站地图文件的[网站地图索引文件](https://www.sitemaps.org/protocol.html#index)的网站。

默认情况下，所有网站地图都会被跟踪。

* `sitemap_alternate_links`

指定是否跟踪一个网址的备用链接。这是在同一 url 块中传递的另一种语言的同一网站链接。

例如：

```HTML
<url>
    <loc>http://example.com/</loc>
    <xhtml:link rel="alternate" hreflang="de" href="http://example.com/de"/>
</url>
```

如果设置了`sitemap_alternate_links`，则会检索到这两个 URL。如果禁用`sitemap_alternate_links`，则只检索`http://example.com/`。

默认情况下禁用`sitemap_alternate_links`。

* `sitemap_filter(entries)`

这是一个过滤器函数，可以重载，根据属性选择网站地图条目。

例如：

```XML
<url>
    <loc>http://example.com/</loc>
    <lastmod>2005-01-01</lastmod>
</url>
```

我们可以定义一个`sitemap_filter`函数来按日期过滤`entries`：

```Python
from datetime import datetime
from scrapy.spiders import SitemapSpider

class FilteredSitemapSpider(SitemapSpider):
    name = "filtered_sitemap_spider"
    allowed_domains = ["example.com"]
    sitemap_urls = ["http://example.com/sitemap.xml"]

    def sitemap_filter(self, entries):
        for entry in entries:
            date_time = datetime.strptime(entry["lastmod"], "%Y-%m-%d")
            if date_time.year >= 2005:
                yield entry
```

这将只检索 2005 年及其后年份修改的`entries`。

Entries 是从网站地图文档中提取的字典对象。通常，key是标签名称，value是标签内的文本。

注意到这很重要：

* 因为 loc 属性是必需的，没有该标签的条目将被丢弃
* 备用链接存储在key为`alternate`的列表中（请参阅`sitemap_alternate_links`）
* 名称空间会被移除，因此命名为`{namespace}tagname`的 lxml 标记只会变成`tagname`

如果省略此方法，将处理在网站地图中找到的所有 entries，同时忽略其他属性及其设置。

将 SitemapSpider 与其他网址来源相结合：

```Python
from scrapy.spiders import SitemapSpider

class MySpider(SitemapSpider):
    sitemap_urls = ["http://www.example.com/robots.txt"]
    sitemap_rules = [
        ("/shop/", "parse_shop"),
    ]

    other_urls = ["http://www.example.com/about"]

    def start_requests(self):
        requests = list(super(MySpider, self).start_requests())
        requests += [scrapy.Request(x, self.parse_other) for x in self.other_urls]
        return requests

    def parse_shop(self, response):
        pass  # ... scrape shop here ...

    def parse_other(self, response):
        pass  # ... scrape other here ...
```
