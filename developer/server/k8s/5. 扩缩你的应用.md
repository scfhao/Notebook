## 运行应用程序的多个实例

在之前的模块中，我们创建了一个 Deployment，然后通过 Service 让其可以开放访问。Deployment 仅为跑这个应用程序创建了一个 Pod。当流量增加时，我们需要扩容应用程序满足用户需求。

扩缩是通过改变 Deployment 中的副本数量来实现的。

扩展 Deployment 将创建新的 Pods，并将资源调度请求分配到有可用资源的节点上，收缩会将 Pods 数量减少至所需的状态。Kubernetes 还支持 Pods 的自动缩放，但这不在本教程的讨论范围内。将 Pods 数量收缩到 0 也是可以的，但这会终止 Deployment 上所有已经部署的 Pods。

运行应用程序的多个实例需要在他们之间分配流量。服务（Service）有一种负载均衡器类型，可以将网络流量均衡分配到外部可访问的 Pods 上。服务将会一直通过端点来监视 Pods 的运行，保证流量只分配到可用的 Pods 上。

一旦有了多个应用实例，就可以没有宕机地滚动更新。我们将在下面的模块中介绍这些。

## 交互教程

### 扩展 Deployment

运行`kubectl get rs`命令来查看 Deployment 创建的副本集（ReplicaSet）。

注意副本集的名称总是`[DEPLOYMENT-NAME]-[RANDOM-STRING]`格式的。随机字符串是使用 pod-template-hash 作为种子随机生成的。

这个命令中两个重要的列：

* DESIRED 展示你创建 Deployment 时定义的期望的应用副本数量。
* CURRENT 展示当前运行的副本数量

下面，我们扩展 Deployment 到 4 副本。我们使用`kubectl scale`命令，跟上 deployment 类型、名称和期望的实例数量：

```SHELL
kubectl scale deployments/kubernetes-bootcamp --replicas=4
```

接下来，让我们检查 Pods 的数量是否有改变：

```SHELL
kubectl get pods -o wide
```

现在这里有 4 个 IP 不同的 Pods 了。异动会注册到 Deployment 事件日志。使用 dexcribe 命令查看：

```SHELL
kubectl describe deployments/kubernetes-bootcamp
```

在这个命令的输出中同样可以看到现在有4个副本了。

### 负载均衡

我们可以使用`describe service`找出暴露的 IP 和端口：

```SHELL
kubectl describe services/kubernetes-bootcamp
```

创建一个值为节点端口的 NODE_PORT 环境变量：

```SHELL
export NODE_PORT=$(kubectl get services/kubernetes-bootcamp -o go-template='{{(index .spec.ports0').nodePort}}')
```

多次执行curl：

```SHELL
curl $(minikube ip):$NODE_PORT
```

每次请求都会击中一个不同的 Pod。这个实例证明负载均衡已经开始工作。

## 收缩

要收缩服务到 2 个副本，还是运行 scale 命令：

```SHELL
kubectl scale deployments/kubernetes-bootcamp --replicas=2
```
