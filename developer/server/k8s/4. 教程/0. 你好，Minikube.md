## 打开仪表盘

有两种方法：

1. 打开一个新的终端，然后运行：

```SHELL
# 启动一个新的终端，并保持此命令运行
minikube dashboard
```

上面的命令会自动打开浏览器，如果不需要打开浏览器，可以使用`--url`标志运行仪表板命令。minikube 会输出一个 URL。

```SHELL
# 启动一个新的终端，并保持此命令运行
minikube dashboard --url
```

http://192.168.3.101/api/v1/namespaces/kubernetes-dashboard/services/http:kubernetes-dashboard:/proxy/

可以通过 ssh 端口转发功能在其他主机上访问 dashboard：

```SHELL
# 在 Mac 上执行时需加 sudo 提权
ssh -L [收听接口:]收听端口:目标主机:目标端口 username@hostname
ssh -L 80:127.0.0.1:44835 scfhao@192.168.3.101
```

## 创建 Deployment

Kubernetes Pod 是由一个或多个为了管理和联网而绑定在一起的容器构成的组。本教程中的 Pod 只有一个容器。Kubernetes Deployment 检查 Pod 的健康状况，并在 Pod 中的容器终止的情况下重新启动新的容器。Deployment 是管理 Pod 创建和扩展的推荐方法。

1. 使用`kubectl create`命令创建管理 Pod 的 Deployment。该 Pod 根据提供的 Docker 镜像运行容器。

```SHELL
# 运行包含 Web 服务器的测试容器景象
kubectl create deployment hello-node --image=registry.k8s.io/e2e-test-images/agnhost:2.39 -- /agnhost netexec --http-port=8080
```

2. 查看`Deployment`:

```SHELL
kubectl get deployments
```

3. 查看 Pod:

```SHELL
kubectl get pods
```

4. 查看集群事件:

```SHELL
kubectl get events
```

5. 查看`kubectl`配置:

```SHELL
kubectl config view
```

有关`kubectl`命令的更多信息，请参阅[kubectl概述](https://kubernetes.io/zh-cn/docs/reference/kubectl/)。

## 创建 Service

默认情况下，Pod 只能通过 Kubernetes 集群中的内部 IP 地址访问。要使得`hello-node`容器可以从 Kubernetes 虚拟网络的外部访问，你必须将 Pod 暴露为 Kubernetes Service。

1. 使用`kubectl expose`命令将 Pod 暴露给公网：

```SHELL
kubectl expose deployment hello-node --type=LoadBanlancer --port=8080
```

这里的`--type=LoadBalancer`参数表明你希望将你的 Service 暴露到集群外部。

测试镜像中的应用程序代码仅监听 TCP 8080 端口。如果你用`kubectl expose`暴露了其他端口，客户端将不能访问其他端口。

2. 查看你创建的 Service:

```
kubectl get services
```

对于支持负载均衡的云服务平台而言，平台将提供一个外部IP来访问该服务。在Minikube 上，`LoadBalancer`使得服务可以通过命令`minikube serivce`访问。

3. 运行下面的命令:

```SHELL
minikube service hello-node
```

这将打开一个浏览器窗口，为你的应用程序提供服务并显示应用的响应。

## 启用插件

Minikube 有一组内置的插件，可以在本地 Kubernetes 环境中启用、禁用和打开。

1. 列出当前支持的插件：

```SHELL
minikube addons list
```

2. 启用插件，例如`metrics-server`：

```SHELL
minikube addons enable metrics-server
```

3. 查看通过安装该插件所创建的 Pod 和 Service:

```SHELL
kubectl get pod,svc -n kube-system
```

4. 禁用`metrics-server`:

```SHELL
minikube addons disable metrics-server
```

## 清理

现在可以清理你在集群中创建的资源：

```SHELL
kubectl delete service hello-node
kubectl delete deployment hello-node
```

停止 Minikube 集群：

```SHELL
minikube stop
```

可选地，删除 Minikube 虚拟机(VM):

```SHELL
minikube delete
```

# [代理和VPN](https://minikube.sigs.k8s.io/docs/handbook/vpn_and_proxy/)

如何在 minikube 上使用 VPN 或者 HTTP/HTTPS 代理

minikube 要求使用 HTTP、HTTPS 和 DNS 协议访问互联网。

## 代理

如果需要通过 HTTP 代理访问网络，你可能需要通过环境变量来传递代理连接信息给 minikube 和 Docker：

* `HTTP_PROXY` - 你的 HTTP 代理地址
* `HTTPS_PROXY` - 你的 HTTPS 代理地址
* `NO_PROXY` - 逗号分隔的不走代理的主机列表

`NO_PROXY`变量很重要：如果没设置它，minikube 可能无法访问 VM 中的资源。minikube 有 4 组默认的 IP 段不需要走代理：

* **192.168.59.0/24**: 用于 minikube VM。为一些 hypervisors 通过`--host-only-cidr`配置。
* **192.168.39.0/24**: 用于 minikube kvm2 驱动。
* **192.168.49.0/24**: 用于 minikube docker 驱动的第一个集群。
* **10.96.0.0/12**: 用于服务集群的 IP。可通过`--service-cluster-ip-range`

一个重要提醒：如果 NO_PROXY 被非 kubernetes 应用依赖，如 Firefox 或 Chrome，你可能需要单独把 minikube IP 添加到逗号分隔列表，因为它们不支持 IP 段。

示例：

macOS 和 Linux

```SHELL
export HTTP_PROXY=http://<proxy hostname:port>
export HTTPS_PROXY=https://<proxy hostname:port>
export NO_PROXY=localhost,127.0.0.1,10.96.0.0/12,192.168.59.0/24,192.168.49.0/24,192.168.39.0/24

minikube start
```

Windows

```DOS
set HTTP_PROXY=http://<proxy hostname:port>
set HTTPS_PROXY=https://<proxy hostname:port>
set NO_PROXY=localhost,127.0.0.1,10.96.0.0/12,192.168.59.0/24,192.168.49.0/24,192.168.39.0/24

minikube start
```
