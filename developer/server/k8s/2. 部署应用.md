# 部署应用

## 使用 kubectl 创建 Deployment

一旦运行了 Kubernetes 集群，就可以在其上部署容器化应用程序。为此，你需要创建 Kubernetes Deployment 配置。Deployment 指挥 Kubernetes 如何创建和更新应用程序的实例。创建 Deployment 后，Kubernetes master 将应用程序实例调度到集群中的各个节点上。

创建应用程序实例后，Kubernetes Deployment 控制器会持续监视这些实例。如果托管实例的节点关闭或被删除，则 Deployment 控制器会将该实例替换为集群中另一个节点上的实例。这提供了一种自我修复机制来解决机器故障维护问题。

创建 Deployment 时，你需要指定应用程序的容器镜像以及要运行的副本数。你可以稍后通过更新 Deployment 来更改该信息。

## kubectl 基础

通用的 kubectl 命令的格式是：kubectl 操作 资源。这样会在指定的资源上执行指定的操作。你可以在命令后面使用`--help`来获取额外的可选参数信息`kubectl get nodes --help`。

## 部署我们的应用

让我们使用如下命令在 Kubernetes 上部署我们的第一个应用：`kubectl create deployment`

我们需要提供部署名称和应用镜像地址（托管在 Docker hub 之外的仓库需要完整的仓库 URL）。

```SHELL
kubectl create deployment kubernetes-bootcamp --image=gcr.io/google-samples/kubernetes-bootcamp:v1

kubectl create deployment kubernetes-bootcamp --image=gcr.lank8s.cn/google-samples/kubernetes-bootcamp:v1
```

恭喜，你已经通过创建 deployment 部署了你的第一个应用。其中会执行的一些操作：

* 搜索一个应用实例可以运行的合适节点
* 使这个应用在节点上运行起来
* 配置集群在需要时在一个新节点上重新运行应用实例

可以使用`kubectl get deployments`命令列出你的部署。

## 查看我们的应用

Kubernetes 中运行的 Pod 是运行在一个私有的、隔离的网络环境。默认情况下仅在 Kubernetes 集群内部可访问。

kubectl 命令可以创建一个代理，这个代理可以通过 control-C 停止，运行期间不会显示任何输出。

我们重新打开一个终端创建来运行代理：

```SHELL
kubectl proxy
```

这样在主机和 Kubernetes 集群之间就建立了代理。可以通过api直接查看版本：

```SHELL
curl http://localhost:8001/version
```

如果 8001 端口不能访问，确认运行了`kubectl proxy`

API 服务器会自动为每个 pod 基于名称创建一个 endpoint，也可以通过代理访问。

首先我们需要获取 pod 名称然后把它存到环境变量 POD_NAME 中：

```SHELL
export POD_NAME=$(kubectl get pods -o go-template --template '{{range.items}}{{.metadata.name}}{{"\n"}}{{end}}')
# 结果是：kubernetes-bootcamp-5b5c68b454-rdp2k
```

你可以通过 API 来获取 Pod：

```SHELL
curl http://localhost:8001/api/v1/namespaces/default/pods/$POD_NAME/
```
