# 创建集群

一个 Kubernetes 集群包含两种类型的资源：

* Master 调度整个集群
* Nodes 负责运行应用

每个 Node 都有 Kubelet，它管理 Node 而且是 Node 与 Master 通信的代理。Node 还应该具有用于处理容器操作的工具，例如 Docker 或 rkt。处理生产级流量的 Kubernetes 集群至少应具有三个 Node，因为如果一个 Node 出现故障其对应的 etcd 成员和控制平面实例都会丢失，并且冗余会受到影响。你可以通过添加更多控制平面节点来降低这种风险。

在 Kubernetes 上部署应用时，你告诉 Master 启动应用容器。Master 就编排容器在集群的 Node 上运行。Node 使用 Master 暴露的 Kubernetes API 与 Master 通信。终端用户也可以使用 Kubernetes API 与集群交互。

## 使用 Minikube 创建集群

```shell
brew install minikube
```

### 启动运行

检查 Minikube 是否安装成功

```
minikube version
```

启动集群

```
minikube start
# 参考笔记./镜像/1. 手动拉取镜像并导入
```

### 集群版本

检查 kubectl 版本，会同时打印客户端版本和服务器版本。客户端版本时 kubectl 的版本，服务器版本是 master 上安装的 Kubernetes 的版本。

```
kubectl version
```

### 集群详情

```
kubectl cluster-info
```

要查看集群中的 Node，可以使用

```
kubectl get nodes
```
