# 蜘蛛

蜘蛛是指定义了如何爬取确定的网站（或网站组），包含了如何爬取和如何从页面中取出结构化的数据的类。换句话说，蜘蛛是对特定的站点实现自定义的爬取和解析页面逻辑的地方。

对于蜘蛛来说，抓取周期是这样的：

1. 生成初始请求以抓取第一个 URL，从这些请求中下载响应后调用指定的回调函数。

要执行的第一个请求是通过调用`start_requests()`方法获得的，该方法（默认情况下）为`start_urls`中指定的 URL 生成`Request`，并将`parse`方法作为`Request`的回调函数。

2. 在回调函数中，将解析响应（网页）并返回数据项对象、`Request`对象或这些对象的可迭代器。这些请求也将包含一个回调函数（也许是相同的），然后 Scrapy 将下载这些请求，并由指定的回调函数处理它们的响应。

3. 在回调函数中，你通常使用选择器（也可以使用 BeautifulSoup、lxml 或其他你喜欢的机制）来解析页面内容，并用解析后的数据生成数据项。

4. 最后，从 spider 返回的项目通常会持久化到数据库（在某些[数据项 pipeline](https://docs.scrapy.org/en/latest/topics/item-pipeline.html#topics-item-pipeline)中）或使用[Feed exports](https://docs.scrapy.org/en/latest/topics/feed-exports.html#topics-feed-exports)写入文件。

尽管这个周期（或多或少）适用于任何类型的蜘蛛，但为了不同的目的，Scrapy 中捆绑了不同类型的默认蜘蛛。我们将在这里讨论这些类型。

## `scrapy.Spider`

这是最简单的蜘蛛，任何其他的蜘蛛都必须继承这个类（包括 Scrapy 中自带的蜘蛛和我们自己写的蜘蛛）。它不提供任何特殊的功能，只提供了一个`start_request()`方法的默认实现，从蜘蛛的`start_urls`属性拿到 URL 发送请求，并对各请求的响应结果调用蜘蛛的`parse`方法。

### `name`

定义蜘蛛名字的字符串。Scrapy 通过蜘蛛的名字来定位和实例化蜘蛛，所以这个名字必须是唯一的。然而，也没规定不能为一个蜘蛛创建多个实例。这个属性是必须写的。

如果蜘蛛只抓取一个域名，通常的做法是用域名来命名蜘蛛，不管有没有顶级域名。例如，抓取`mywebsite.com`的蜘蛛通常被称为`mywebsite`。

### `allowed_domains`

一个可选的字符串列表，包含允许该蜘蛛抓取的域名。如果启用了`OffsiteMiddleware`，不属于此列表中指定的域名（或其子域名）的 URL 请求将不会被跟踪。

假设您的目标网址是`https://www.example.com/1.html`，那么在列表中添加 "example.com"。

### `start_urls`

在未指定特定 URL 的情况下，蜘蛛将开始抓取的 URL 列表。因此，首先下载的网页将是此处列出的网页。随后的`Request`将根据起始 URL 中的数据陆续生成。

### `custom_settings`

一个设置字典，在运行此蜘蛛时将从项目配置中覆盖这些设置。由于设置会在实例化之前更新，因此必须将其定义为类属性。

有关可用内置设置的列表，请参阅：[内置设置参考](https://docs.scrapy.org/en/latest/topics/settings.html#topics-settings-ref)。

### `crawler`

在类初始化后，该属性由`from_crawler()`类方法设置，并链接至该 spider 实例所绑定的`Crawler`对象。

爬虫（Crawlers）在项目中封装了许多组建，以便于单一入口访问（如扩展、中间件、信号管理器等）。如需了解更多，请参阅[爬虫API](https://docs.scrapy.org/en/latest/topics/api.html#topics-api-crawler)。

### `settings`

运行该蜘蛛的配置。这是一个`Settings`实例，有关详细介绍，请参阅[Settings](https://docs.scrapy.org/en/latest/topics/settings.html#topics-settings)主题。

### `logger`

以 Spider 的`name`创建的 Python 日志记录器。你可以使用它来发送日志信息，如[Spider 的日志记录](https://docs.scrapy.org/en/latest/topics/logging.html#topics-logging-from-spiders)所述。

### `state`

您可以用它在不同批次(batches)之间持续保持某些蜘蛛状态。有关详情，请参阅[在批次间保持持久状态](https://docs.scrapy.org/en/latest/topics/jobs.html#topics-keeping-persistent-state-between-batches)。

### `from_crawler(crawler, *args, **kwargs)`

这是 Scrapy 用来创建蜘蛛的类方法。

你可能不需要直接重写它，因为默认实现代理到`__init__()`方法，使用给定参数`args`和命名参数`kwargs`调用它。

不过，该方法会在新实例中设置`crawler`和`settings`属性，以便以后在蜘蛛代码中访问它们。

2.11 版中的更改：爬虫设置`crawler.settings`中的设置现在可以在此方法中修改，这对于根据参数修改设置非常方便。因此，这些设置并不是最终值，因为它们可以在以后被附加组件等修改。出于同样的原因，大多数`Crawler`属性在此时都没有初始化。

最终的`settings`和初始化的`Crawler`属性可在`start_requests()`方法、engine_started 信号的处理程序及后续程序中使用。

参数说明：

* crawler(Crawler示例)-当前蜘蛛将绑定的爬虫
* args(list)-传递到`__init__()`方法的参数
* kwargs(dict)-传递到`__init__()`方法的关键字参数

### `classmethod update_settings(settings)`

`update_settings()`方法用于修改 spider 的设置，在初始化 spider 实例时被调用。

它以`Settings`对象为参数，可以添加或更新蜘蛛的配置值。该方法是一个类方法，即在蜘蛛类中调用，允许蜘蛛的所有实例共享相同的配置。

虽然可以在`custom_settings`中设置每个蜘蛛的`settings`，但使用`update_settings()`，可以根据其他设置、蜘蛛属性或其他因素动态添加、删除或更改设置，并使用`'spider'`以外的设置优先级。此外，在子类中通过重载`update_settings()`很容易进行扩展，而在`custom_settings`中做同样的事情却很难。

例如，假设蜘蛛需要修改`FEEDS`：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"
    custom_feed = {
        "/home/user/documents/items.json": {
            "format": "json",
            "indent": 4,
        }
    }

    @classmethod
    def update_settings(cls, settings):
        super().update_settings(settings)
        settings.setdefault("FEEDS", {}).update(cls.custom_feed)
```

### `start_requests()`

该方法必须返回一个迭代器，其中包含该蜘蛛要抓取的第一批请求。Scrapy 在打开蜘蛛进行抓取时会调用该方法。Scrapy 只调用一次，因此将`start_requests()`作为生成器来实现是安全的。

默认实现会为`start_urls`中的每个 url 生成`Request(url,dont_filter=True)`。

如果要更改用于启动域名抓取的请求，可以覆盖此方法。例如，如果需要使用 POST 请求登录，可以这样做：

```Python
import scrapy

class MySpider(scrapy.Spider):
    name = "myspider"

    def start_requests(self):
        return [
            scrapy.FormRequest(
                "http://www.example.com/login",
                formdata={"user": "john", "pass": "secret"},
                callback=self.logged_in,
            )
        ]

    def logged_in(self, response):
        # here you would extract links to follow and return Requests for
        # each of them, with another callback
        pass
```

### `parse(response)`

当请求未指定回调时，这是 Scrapy 用来处理下载响应的默认回调。

`parse`方法负责处理响应，并返回刮擦数据和/或更多要跟踪的 URL。其他请求回调的要求与`Spider`类相同。

此方法以及任何其他请求回调都必须返回一个请求对象、一个项目对象、一个请求对象和/或项目对象的可迭代器，或无。
