我们编写 Makefile 的时候可以使用的文件的名称“GNUmakefile”、“makefile”、“Makefile”，make 执行时会去寻找 Makefile 文件，寻找的顺序也是这样的。

## Makefile 的工作流程

```Makefile
main:main.o test1.o test2.o
gcc main.o test1.o test2.o -o main
main.o:main.c test.h
gcc -c main.c -o main.o
test1.o:test1.c test.h
gcc -c test1.c -o test1.o
test2.o:test2.c test.h
gcc -c test2.c -o test2.o
```

在我们编译项目文件的时候，默认的情况下，make 执行的是 Makefile 中的第一规则（Makefile 中出现的第一个依赖关系），此规则的第一目标称之为“最终目标”或者是“终极目标”。

在示例中，目标 main 在 Makefile 中是第一个目标，因此它就是 make 的终极目标，当修改过任何 C 文件后，执行 make 将会重建终极目标 main。

对于 main 的依赖文件作为目标的规则处理有下列三种情况：

* 目标“.o”文件不存在，使用其描述规则创建它；
* 目标“.o”文件存在，目标“.o”文件所依赖的“.c”源文件“.h”文件中的任何一个比目标“.o”文件更新，则根据规则重新编译生成它；
* 目标“.o”文件存在，目标“.o”文件比它的任何一个依赖文件（“.c”源文件、“.h”文件）更新，则什么也不做。

## 清除工作目录中的过程文件

我们在使用的时候会产生中间文件会让整个文件看起来很乱，所以在编写 Makefile 文件的时候会在末尾加上这样的规则语句：

```
.PHONY:clean
clean:
	rm -rf *.o test
```

其中“*.o”是执行过程中产生的中间文件，“test”是最终生成的执行文件。我们可以看到 clean 是独立的，它只是一个伪目标，不是具体的文件。不会与第一个目标文件相关联，所以我们在执行 make 的时候也不会执行下面的命令。在 shell 中执行“make clean”命令，编译时的中间文件和生成的最终目标文件都会被清除，方便我们下次的使用。
