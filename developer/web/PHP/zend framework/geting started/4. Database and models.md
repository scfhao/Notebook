# 数据库和模型

## 数据库

现在我们已经使用控制器动作方法和视图脚本设置了专辑模块，现在是查看我们应用程序的模型部分的时候了。 请记住，该模型是处理应用程序核心目标（所谓的“业务规则”）的一部分，在我们的例子中涉及数据库。 我们将利用zend-db的Zend \ Db\TableGateway\TableGateway从数据库表中查找，插入，更新和删除行。

我们将通过PHP的PDO驱动程序使用Sqlite。 创建一个包含以下内容的文本文件data/schema.sql：

```
CREATE TABLE album (id INTEGER PRIMARY KEY AUTOINCREMENT, artist varchar(100) NOT NULL, title varchar(100) NOT NULL);
INSERT INTO album (artist, title) VALUES ('The Military Wives', 'In My Dreams');
INSERT INTO album (artist, title) VALUES ('Adele', '21');
INSERT INTO album (artist, title) VALUES ('Bruce Springsteen', 'Wrecking Ball (Deluxe)');
INSERT INTO album (artist, title) VALUES ('Lana Del Rey', 'Born To Die');
INSERT INTO album (artist, title) VALUES ('Gotye', 'Making Mirrors');
```

（选择的测试数据是在撰写本文时亚马逊的畅销作品！）

现在使用以下命令创建数据库：

```
$ sqlite data/zftutorial.db < data/schema.sql
```

一些系统，包括Ubuntu，使用命令sqlite3; 检查您的系统上使用哪一个。

使用PHP创建数据库

如果您的系统上没有安装Sqlite，则可以使用PHP使用先前创建的相同SQL模式文件来加载数据库。 创建具有以下内容的文件数据/ load_db.php：

```
<?php
$db = new PDO('sqlite:' . realpath(__DIR__) . '/zftutorial.db');
$fh = fopen(__DIR__ . '/schema.sql', 'r');
while ($line = fread($fh, 4096)) {
    $db->exec($line);
}
fclose($fh);
```

一旦创建，执行它：

```
$ php data/load_db.php
```

我们现在在数据库中有一些数据，可以为它写一个非常简单的模型。

## 模型文件

Zend Framework不提供zend-model组件，因为该模型是您的业务逻辑，由您决定如何使其运行。 根据您的需要，您可以使用许多组件。 一种方法是使模型类表示应用程序中的每个实体，然后使用将实体加载并保存到数据库的映射对象。 另一个是使用对象关系映射（ORM）技术，如Doctrine或Propel。

对于本教程，我们将通过创建一个使用Zend\Db\TableGateway\TableGateway的AlbumTable类来创建一个模型，并且每个相册将被表示为一个Album对象（称为实体）。 这是表数据网关设计模式的实现，以允许与数据库表中的数据进行接口。 但请注意，表数据网关模式在较大的系统中可能会成为限制。 还有一个诱惑，将数据库访问代码放入控制器操作方法，因为这些都是由Zend\Db\TableGateway\AbstractTableGateway公开的。 不要这样做！

我们首先在模块/Album/src/Model下创建一个名为Album.php的文件：

```
namespace Album\Model;

class Album
{
    public $id;
    public $artist;
    public $title;

    public function exchangeArray(array $data)
    {
        $this->id     = !empty($data['id']) ? $data['id'] : null;
        $this->artist = !empty($data['artist']) ? $data['artist'] : null;
        $this->title  = !empty($data['title']) ? $data['title'] : null;
    }
}
```

我们的专辑实体对象是一个PHP类。 为了使用zend-db的TableGateway类，我们需要实现exchangeArray（）方法; 此方法将数据从提供的数组复制到实体的属性。 稍后将添加一个输入过滤器，以确保注入的值有效。

接下来，我们在模块/ Album / src / Model目录中创建我们的AlbumTable.php文件，如下所示：

```
namespace Album\Model;

use RuntimeException;
use Zend\Db\TableGateway\TableGatewayInterface;

class AlbumTable
{
    private $tableGateway;

    public function __construct(TableGatewayInterface $tableGateway)
    {
        $this->tableGateway = $tableGateway;
    }

    public function fetchAll()
    {
        return $this->tableGateway->select();
    }

    public function getAlbum($id)
    {
        $id = (int) $id;
        $rowset = $this->tableGateway->select(['id' => $id]);
        $row = $rowset->current();
        if (! $row) {
            throw new RuntimeException(sprintf(
                'Could not find row with identifier %d',
                $id
            ));
        }

        return $row;
    }

    public function saveAlbum(Album $album)
    {
        $data = [
            'artist' => $album->artist,
            'title'  => $album->title,
        ];

        $id = (int) $album->id;

        if ($id === 0) {
            $this->tableGateway->insert($data);
            return;
        }

        if (! $this->getAlbum($id)) {
            throw new RuntimeException(sprintf(
                'Cannot update album with identifier %d; does not exist',
                $id
            ));
        }

        $this->tableGateway->update($data, ['id' => $id]);
    }

    public function deleteAlbum($id)
    {
        $this->tableGateway->delete(['id' => (int) $id]);
    }
}
```

这里有很多事情。 首先，我们将保护属性$ tableGateway设置为在构造函数中传递的TableGateway实例，暗示了TableGatewayInterface（允许我们轻松提供替代实现，包括测试期间的模拟实例）。 我们将使用它来对我们的相册的数据库表执行操作。

然后，我们创建一些我们的应用程序将用于与表网关连接的帮助方法。 fetchAll（）作为ResultSet从数据库中检索所有相册行，getAlbum（）将作为Album对象检索单个行，saveAlbum（）可以在数据库中创建一个新行，或更新已存在的行，deleteAlbum（）将删除 行完全。 这些方法中的每一个方法的代码都是期望的、不言自明的。

## 使用 ServiceManager 来配置表格网关并注入 AlbumTable

为了始终使用我们的AlbumTable的相同实例，我们将使用ServiceManager来定义如何创建一个。 这在Module类中最容易完成，我们创建一个名为getServiceConfig（）的方法，该方法由ModuleManager自动调用并应用于ServiceManager。 然后，我们可以在需要时获取到它。

要配置ServiceManager，我们可以提供要实例化的类的名称，或者在ServiceManager需要的时候提供实例化对象的工厂（工厂类的闭包，回调或类名）。 我们首先实现getServiceConfig（）来提供一个创建一个AlbumTable的工厂。 将此方法添加到模块/Album/src/Module.php文件的底部：

```
namespace Album;

// Add these import statements:
use Zend\Db\Adapter\AdapterInterface;
use Zend\Db\ResultSet\ResultSet;
use Zend\Db\TableGateway\TableGateway;
use Zend\ModuleManager\Feature\ConfigProviderInterface;

class Module implements ConfigProviderInterface
{
    // getConfig() method is here

    // Add this method:
    public function getServiceConfig()
    {
        return [
            'factories' => [
                Model\AlbumTable::class => function($container) {
                    $tableGateway = $container->get(Model\AlbumTableGateway::class);
                    return new Model\AlbumTable($tableGateway);
                },
                Model\AlbumTableGateway::class => function ($container) {
                    $dbAdapter = $container->get(AdapterInterface::class);
                    $resultSetPrototype = new ResultSet();
                    $resultSetPrototype->setArrayObjectPrototype(new Model\Album());
                    return new TableGateway('album', $dbAdapter, null, $resultSetPrototype);
                },
            ],
        ];
    }
}
```

此方法返回一个工厂数组，在将它们传递到ServiceManager之前，ModuleManager将它们全部合并在一起。 Album \ Model \ AlbumTable的工厂使用ServiceManager创建一个Album \ Model \ AlbumTableGateway服务，代表一个TableGateway传递给其构造函数。 我们还告诉ServiceManager，通过获取Zend \ Db \ Adapter \ AdapterInterface实现（也来自ServiceManager）并使用它创建一个TableGateway对象来创建AlbumTableGateway服务。 每当它创建一个新的结果行时，TableGateway被要求使用Album对象。 TableGateway类使用原型模式来创建结果集和实体。 这意味着，不需要在需要时实例化，系统将克隆以前实例化的对象。 有关详细信息，请参阅PHP构造函数最佳实践和原型模式。

> 工厂
> 上面的例子显示了在你的模块类中建立工厂作为闭包。 另一种选择是将工厂构建为一个类，然后将该类映射到模块配置中。 这种方法有很多好处：
> - 除非调用工厂，否则代码不会被解析或执行。
> - 您可以轻松地对工厂进行单元测试，以确保它能够做到这一点。
> - 如果需要，您可以扩展工厂。
> - 您可以在具有相关构造的多个实例中重新使用工厂。

zend-servicemanager文档中介绍了创建工厂的内容。

Zend \ Db \ Adapter \ AdapterInterface服务由zend-db组件注册。 您可能已经注意到config / modules.config.php包含以下条目：

```
return [
    'Zend\Form',
    'Zend\Db',
    'Zend\Router',
    'Zend\Validator',
    /* ... */
],
```

提供zend-servicemanager配置的所有Zend Framework组件也作为模块本身暴露出来; 在初始安装期间注册组件的提示确保为您创建上述条目。

最终的结果是我们可以依靠一个Zend \ Db \ Adapter \ AdapterInterface服务的工厂; 现在我们需要提供配置，因此可以为我们创建适配器。

Zend Framework的ModuleManager将每个模块的module.config.php文件中的所有配置合并，然后合并到config / autoload /（第一个* .global.php文件，然后是* .local.php文件）中的文件中。 我们将把我们的数据库配置信息添加到global.php，您应该将其提交给版本控制系统。 您可以使用local.php（在VCS之外）来存储数据库的凭据。 使用以下代码修改config / autoload / global.php（在项目根目录，不在专辑模块内）

```
return [
    'db' => [
        'driver' => 'Pdo',
        'dsn'    => sprintf('sqlite:%s/data/zftutorial.db', realpath(getcwd())),
    ],
];
```

如果您正在配置需要凭据的数据库，则可以将config / autoload / global.php中的一般配置，然后在config / autoload / local.php中配置当前环境，包括DSN和凭据。 文件。 当应用程序运行时，这些将合并，确保您具有完整的定义，但允许您将凭证保留在版本控制之外。

## 回到控制器

现在我们有一个模型，我们需要把它注入我们的控制器，所以我们可以使用它。

首先，我们将向控制器添加一个构造函数。 打开文件模块/ Album / src / Controller / AlbumController.php，并添加以下属性和构造函数：

```
namespace Album\Controller;

// Add the following import:
use Album\Model\AlbumTable;
use Zend\Mvc\Controller\AbstractActionController;
use Zend\View\Model\ViewModel;

class AlbumController extends AbstractActionController
{
    // Add this property:
    private $table;

    // Add this constructor:
    public function __construct(AlbumTable $table)
    {
        $this->table = $table;
    }

    /* ... */
}
```

我们的控制器现在取决于AlbumTable，所以我们需要为控制器创建一个工厂。 类似于我们为模型创建工厂，我们将在我们的Module类中创建它，只有这一次，在一个新的方法Album \ Module :: getControllerConfig（）下：

```
namespace Album;

use Zend\Db\Adapter\Adapter;
use Zend\Db\ResultSet\ResultSet;
use Zend\Db\TableGateway\TableGateway;
use Zend\ModuleManager\Feature\ConfigProviderInterface;

class Module implements ConfigProviderInterface
{
    // getConfig() and getServiceConfig methods are here

    // Add this method:
    public function getControllerConfig()
    {
        return [
            'factories' => [
                Controller\AlbumController::class => function($container) {
                    return new Controller\AlbumController(
                        $container->get(Model\AlbumTable::class)
                    );
                },
            ],
        ];
    }
}
```

因为我们现在正在定义我们自己的工厂，我们可以修改我们的module.config.php来删除定义。 打开模块/ Album / config / module.config.php并删除以下行：

```
<?php
namespace Album;

// Remove this:
use Zend\ServiceManager\Factory\InvokableFactory;

return [
    // And remove the entire "controllers" section here:
    'controllers' => [
        'factories' => [
            Controller\AlbumController::class => InvokableFactory::class,
        ],
    ],

    /* ... */
];
```

当我们需要与我们的模型进行交互时，我们现在可以从我们的控制器中访问属性$ table。

## 列出专辑

为了列出专辑，我们需要从模型中检索，并将它们传递给视图。 为此，我们在AlbumController中填入indexAction（）。 更新AlbumController :: indexAction（），如下所示：

```
// module/Album/src/Controller/AlbumController.php:
// ...
    public function indexAction()
    {
        return new ViewModel([
            'albums' => $this->table->fetchAll(),
        ]);
    }
// ...
```

使用Zend Framework，为了在视图中设置变量，我们返回一个ViewModel实例，其中构造函数的第一个参数是一个包含我们希望表示的数据的数组。 然后，这些将自动传递到视图脚本。 ViewModel对象还允许我们更改所使用的视图脚本，但默认情况是使用{module name} / {controller name} / {action name}。 我们现在可以填写index.phtml视图脚本：

```
<?php
// module/Album/view/album/album/index.phtml:

$title = 'My albums';
$this->headTitle($title);
?>
<h1><?= $this->escapeHtml($title) ?></h1>
<p>
    <a href="<?= $this->url('album', ['action' => 'add']) ?>">Add new album</a>
</p>

<table class="table">
<tr>
    <th>Title</th>
    <th>Artist</th>
    <th>&nbsp;</th>
</tr>
<?php foreach ($albums as $album) : ?>
    <tr>
        <td><?= $this->escapeHtml($album->title) ?></td>
        <td><?= $this->escapeHtml($album->artist) ?></td>
        <td>
            <a href="<?= $this->url('album', ['action' => 'edit', 'id' => $album->id]) ?>">Edit</a>
            <a href="<?= $this->url('album', ['action' => 'delete', 'id' => $album->id]) ?>">Delete</a>
        </td>
    </tr>
<?php endforeach; ?>
</table>
```

我们要做的第一件事就是设置页面的标题（在布局中使用），并使用headTitle（）视图助手来设置<head>部分的标题，该助手将显示在浏览器的标题栏中。 然后，我们创建一个链接添加一个新的相册。

url（）视图助手是由zend-mvc和zend-view提供的，用来创建我们需要的链接。 url（）的第一个参数是我们希望用来构造URL的路由名称，第二个参数是要替换为路由占位符的变量数组。 在这种情况下，我们使用我们设置的相册路由来接受两个占位符变量：action和id。

我们遍历从控制器操作中分配的$相册。zend-view自动确保将这些变量提取到视图脚本的范围内; 您也可以使用$ this -> {variable name}来访问它们，以便区分提供给视图脚本的变量和其中创建的变量。

然后，我们创建一个表格来显示每个专辑的标题和艺术家，并提供允许编辑和删除记录的链接。 一个标准的foreach循环被用来迭代专辑列表，我们使用冒号和endforeach替代形式; 因为它比扫描试图匹配大括号更容易。 同样，url（）视图助手用于创建编辑和删除链接。

> 逃逸 Escaping
> 我们总是使用escapeHtml()视图助手来帮助保护自己免受跨站点脚本（XSS）漏洞的攻击。

如果您打开http://localhost:8080/album（或者如果您使用的是自托管的Apache，则为http://zf-tutorial.localhost/album），您应该看到当前的列表效果。
