# 路由和控制器

我们将建立一个非常简单的库存系统来显示我们的专辑集合。 主页将列出我们的收藏，并允许我们添加，编辑和删除相册。 因此需要以下页面：

页面 | 描述
------|--------------------
Home | 这将显示相册列表，并提供编辑和删除它们的链接。 此外，还将提供启用添加新相册的链接。
Add new album | 此页面将提供添加新相册的表单。
Edit album | 此页面将提供编辑相册的表单。
Delete album | 此页面将确认我们要删除相册，然后将其删除。

在我们设置文件之前，了解框架如何组织页面很重要。 应用程序的每一页被称为一个动作，动作被分组到模块内的控制器中。 因此，您通常将相关操作分组到控制器中; 例如，新闻控制器可能会有当前，存档和查看的动作。

由于我们有四个页面都适用于专辑，因此我们将把它们分组在我们的相册模块中的单个控制器AlbumController中作为四个操作。 四个行动将是：

页面 | 控制器 | 动作
------|---------|-------------------
Home | AlbumController | index
Add new album | AlbumController | add
Edit album | AlbumController | edit
Delete album | AlbumController | delete

URL到特定操作的映射是使用在模块的module.config.php文件中定义的路由来完成的。 我们将为我们的相册操作添加路由。 这是更新的模块配置文件，新代码使用注释突出显示。

```
namespace Album;

use Zend\Router\Http\Segment;
use Zend\ServiceManager\Factory\InvokableFactory;

return [
    'controllers' => [
        'factories' => [
            Controller\AlbumController::class => InvokableFactory::class,
        ],
    ],

    // The following section is new and should be added to your file:
    'router' => [
        'routes' => [
            'album' => [
                'type'    => Segment::class,
                'options' => [
                    'route' => '/album[/:action[/:id]]',
                    'constraints' => [
                        'action' => '[a-zA-Z][a-zA-Z0-9_-]*',
                        'id'     => '[0-9]+',
                    ],
                    'defaults' => [
                        'controller' => Controller\AlbumController::class,
                        'action'     => 'index',
                    ],
                ],
            ],
        ],
    ],

    'view_manager' => [
        'template_path_stack' => [
            'album' => __DIR__ . '/../view',
        ],
    ],
];
```

路线的名称是“专辑”，并且具有“段”的类型。 段路由允许我们在URL模式（路由）中指定将被映射到匹配路由中的命名参数的占位符。 在这种情况下，路由是/ album [/：action [/：id]]，它将匹配以/ album开头的所有URL。 下一个段将是一个可选的操作名称，然后最后一个段将被映射到一个可选的ID。 方括号表示一个段是可选的。 约束部分允许我们确保段内的字符与预期的一致，所以我们限制了操作为以字母开始，然后后续字符只能是字母数字，下划线或连字符。 我们也将id限制为数字。

此路由允许我们拥有以下URL：

URL | Page | Action
------|-------|---------------------
/album | Home(list of albums) | index
/album/add | Add new album | add
/album/edit/2 | Edit album with an id of 2 | edit
/album/delete/4 | Delete album with an id of 4 | delete

## 创建控制器

我们现在准备建立我们的控制器了。 对于zend-mvc，控制器是通常称为{Controller name}Controller的类; 请注意{Controller name}必须以大写字母开头。 该类生活在模块的Controller子目录中的一个名为{Controller name} Controller.php的文件中; 在我们的例子中是module/Album/src/Controller/。 每个动作是控制器类中的一个公共方法，名为{action name} Action，其中{action name}应以小写字母开头。

> 约定不是严格强制的
> 这是按惯例。 zend-mvc不对控制器提供许多限制，除了它们必须实现Zend \ Stdlib \ Dispatchable接口之外。 该框架为我们提供了两个抽象类：Zend \ Mvc \ Controller \ AbstractActionController和Zend \ Mvc \ Controller \ AbstractRestfulController。 我们将使用标准的AbstractActionController，但如果您打算编写RESTful Web服务，则AbstractRestfulController可能很有用。

我们继续在文件zf-tutorials / module / Album / src / Controller / AlbumController.php中创建我们的控制器类：

```
namespace Album\Controller;

use Zend\Mvc\Controller\AbstractActionController;
use Zend\View\Model\ViewModel;

class AlbumController extends AbstractActionController
{
    public function indexAction()
    {
    }

    public function addAction()
    {
    }

    public function editAction()
    {
    }

    public function deleteAction()
    {
    }

```

我们现在已经设置了我们要使用的四个动作。 直到我们设立视图，他们才会工作。 每个动作的网址是：

URL | Method called
------|------------------------------
http://zf-tutorial.localhost/album | Album\Controller\AlbumController::indexAction
http://zf-tutorial.localhost/album/add | Album\Controller\AlbumController::addAction
http://zf-tutorial.localhost/album/edit | Album\Controller\AlbumController::editAction
http://zf-tutorial.localhost/album/delete | Album\Controller\AlbumController::deleteAction

我们现在有一个工作路由器，并为我们的应用程序的每一页设置了动作。

现在是建立视图和模型层的时候了。

## 初始化视图脚本

要将视图集成到我们的应用程序中，我们需要创建一些视图脚本文件。 这些文件将由DefaultViewStrategy执行，并将传递从controller操作方法返回的任何变量或视图模型。 这些视图脚本存储在我们的模块的视图目录中，该目录位于控制器后面的目录中。 立即创建这四个空文件：

* module/Album/view/album/album/index.phtml
* module/Album/view/album/album/add.phtml
* module/Album/view/album/album/edit.phtml
* module/Album/view/album/album/delete.phtml

我们现在可以开始填补所有内容，从我们的数据库和型号开始。
