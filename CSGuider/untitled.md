# 数据结构不难：能不能写一个元素类型通用的数据结构？

本文讲解教科书上的顺序表为什么不是类型通用的，然后给出一种类型通用的顺序表的 C 语言实现方式。

我在学校学数据结构这门课的时候，一直有一个问题：数据结构的代码需要自己写吗？是不是已经有人写好自己直接调用就好了？

时隔多年以后，我现在可以给出当年的我一个答案：数据结构的代码不一定要自己写，重要的是实现思想，在需要自己写的时候，自己要有能力写出来。

相信很多同学也会有这样的困惑，你可能想过，把书上的每个数据结构的代码都敲进代码文件里保存好，以后用的时候直接用。这个想法很好，但我希望通过这篇文章可以让你放弃这种想法。

> 由于讲“数据结构”范围太大，本文后面的内容都以最简单的顺序表为例，但是其他数据结构也都或多或少存在这样的问题。

## 类型不通用

教科书上的这个顺序表是类型不通用的，这里稍微介绍一下原因：

1. 使用`typedef XX ElemType`定义的元素类型，所以`ElemType`的具体类型在编译时是唯一的、确定的，不能通过代码再修改这种类型，比如下面的代码会报错：

```C
// 要在顺序表中存放 char 类型的数据，所以定义 ElemType 为 char
typedef char ElemType;
// ...
// 在同一個程序中又想用順序表存放 int 类型的数据
typedef int ElemType;
```

2. 对于学过 C++ 等语言的同学可能会提出函数重载，所谓函数重载就是可以写多个同名但参数不同的函数，程序运行时会自动根据实参的类型来判断该调用哪个函数。但是，C 语言是不支持函数重载的，也就是说下面的代码也会报错：

```C
// 用于 char 类型的顺序表插入函数
Status ListInsert_Sq(SqList *L, int i, char e) {
    // ...
}

// 用于 int 类型的顺序表插入函数
Status ListInsert_Sq(SqList *L, int i, int e) {
    // ...
}
```

所以，即使你可以把顺序表的代码复制出一份来，两个顺序表的各函数的函数名也不能一样。

> 另外，C 语言也不支持别的语言中的“泛型”的概念。

基于以上的原因，似乎写一次顺序表的代码，然后在所有需要的地方使用的想法似乎是不能完成了。所以数据结构还是要学好，这样当以前写的数据结构不能用的时候，自己写一个出来嘛。当然还是那句话，学思想，而不要死记代码，因为现在是用 C 语言，之后用到的时候可能是另一种语言，代码肯定是不一样的。

## 写一个类型通用的顺序表

遇到一点挫折就放弃，那不是程序员的风格。

### 万能类型指针

先介绍一下`void *`（无类型指针），可以对`void *`变量赋值其他任何类型的指针值。也就是说，`void *`可以和其他类型的指针变量之间做强制类型转换（甚至可以和二级指针做类型转换）。

另外还需要掌握的是，对`void *`指针做算术运算时，比如`+1`时，指针向后移动`1字节`。

### 实现思想

在 C 语言中，不管是变量、常量还是函数，在程序运行的过程中都是内存中的一段二进制，所以对于不同类型的值，我们只需要关注其在内存中的起始地址及占内存长度即可，可以用`void *`指向其内存的起始地址，然后再定义一个变量代表该类型在内存中的长度即可。
